# 全局项目执行标准（Global Project Execution Standard）

> WORK-LAB 负责的全局层规范——一套执行标准，适配所有软件 + 所有项目。
> 依据：2026-08-23 调研（AGENTS.md best practice / SKILL.md 触发机制 / 并行 agent 编排）。

## 一、三层结构定位

```
① 全局层（本文档）：一套执行标准，所有软件 + 所有项目共同遵守
② 项目层：各项目 AGENTS.md + SKILL（各自内部，引用全局标准）
③ 软件层：各软件自身配置
```

## 二、执行生命周期（一个任务怎么跑）

```
① 任务理解 → ② 技能扫描(强制) → ③ 任务分片 → ④ 执行 → ⑤ 验证 → ⑥ 落地
```

| 步骤 | 动作 | 要点 |
|---|---|---|
| ① 任务理解 | 明确目标/边界/验收标准/非目标 | 不明确先问 |
| ② 技能扫描 | **执行前扫描可用 SKILL，加载匹配的** | 命中即加载技能指令再干；未命中直接干（不阻塞）|
| ③ 任务分片 | 大任务拆独立单元（模块/路径/依赖边界）| 可并行分片 |
| ④ 执行 | 按加载技能 + 项目 AGENTS.md 规则干活 | 遵守项目规则 + 全局边界 |
| ⑤ 验证 | 本地测试 + 质量门（按变更域，不全量一刀切）| 分片级验证 |
| ⑥ 落地 | 漂移检查 → 审计 → 合并（并行框架：worktree + 队列）| 漂移检测（project_drift_check）通过 + 审计通过才落地 |

### 多轮任务防漂移（落地前必查）

```
多轮任务后项目可能漂移（基线 vs 实际偏离），落地前强制执行：
  工具：10-workflow/workflow-assistance/scripts/workflow/project_drift_check.py
  - record_baseline(root)：记录基线快照（干净验证后）
  - check_drift(root)：对比当前 vs 基线，报告漂移文件
  - converge(root)：确认漂移为新基线（或修复后重记）
  漂移 → 先报告/收敛，不直接落地；干净 → 才允许合并
```

## 三、技能强制调用（解决"直接开干"）

```
各软件执行任务前，强制执行步骤②：
  1. 先查项目技能调用索引（.hermes/skill-call-index.json）
     → 命中 → 直接调用技能（不重复扫描）
  2. 索引未命中 → 扫描技能清单（SKILL.md description）
     → 匹配 → 加载技能执行 + 记录到索引（下次直接命中）
  3. 仍未命中 → 直接执行（不阻塞）

技能调用索引（优化，避免每次扫描）：
  工具：10-workflow/workflow-assistance/scripts/workflow/skill_call_index.py
  - build(root, skills_dir)：首次扫描建索引（keyword → skills）
  - lookup(root, task)：任务关键词查索引（直接返回匹配技能）
  - record(root, task, skill)：学习新映射（任务→技能）
  每项目一个索引文件，后续相同任务直接调用，无需每次扫描

触发机制（借鉴 Claude Code skills）：
  model-invocable：description 语义匹配，模型自动调用
  user-invocable：用户显式调用
  项目规则（AGENTS.md）明确：执行前先扫描 SKILL
```

## 四、并行执行（替代单写者）

```
任务分片（③）→ 每分片独立 worktree 并行写 → 审计（⑤）→ 队列合并（⑥）
- 单软件项目内多实例并行
- 多软件同项目分任务并行
- 路径级所有权（advisory 认领，重叠才排队）
```

## 五、全局边界（所有软件+项目遵守）

```
1. 安全：非明确授权禁止访问 E:\ 数据盘
2. 数据边界：各项目构建缓存/产品资产留在自己项目内，禁止外溢/漂移
3. 官方优先：软件更新以官方发布为准，禁私自本地打包
4. 全功率：无限流/降级，模型官方默认
5. 审计分层：按变更域跑（不全量一刀切），合并前全量
```
