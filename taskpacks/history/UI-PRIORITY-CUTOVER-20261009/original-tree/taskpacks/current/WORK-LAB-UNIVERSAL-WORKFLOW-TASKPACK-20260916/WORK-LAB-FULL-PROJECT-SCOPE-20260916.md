## 4. 五维基线不变

以已读取的固定 AGENTS 原文为依据，五维仍是：
1. 每软件唯一权威入口（同一官方安装的 GUI/CLI 不等于冲突）；
2. 适用 GUI 的桌面入口；
3. 官方标准＋用户配置；
4. 轻量、按需、不产生阻塞开销；
5. 任务级模型策略：质量、成本、隐私、延迟，尊重用户模型和推理设置，不新增全局费用/限速上限。

这五项不能被其它历史摘要里的五条安全要求替代。安全与数据边界同样保留，但不是另命名一套“五维”。

## 5. 必须避免的四种职责丢失

### 5.1 只读 Observer ≠ WORK-LAB 全部只读

合法配置管理与控制职责保留：Plan/Approve/Apply/Readback/Restore 分别处理，按现有授权和原生接口执行。Observer 继续严格只读。H4 和 H5 都支持这个区别。实现采用命令、原生界面、已有服务还是其它受支持表面，应依有效后续决策；不是本次自动批准再造独立控制台。

### 5.2 不自研重复运行时 ≠ 删除任务自动化

可以减少自己的 worker/调度/上下文重复实现，但任务分工、连续执行、检查点、恢复、结果回传和真实验收依然是职责。原生或成熟方案替代后，需要证明同样的用户能力得到承接。

### 5.3 不复制私人会话库 ≠ 删除 Memory/Growth

保留获准的工作流经验与技能成长。来源、作用域、冲突、TTL、晋级与回退属于治理内容；全量原生会话、浏览器数据、账号密钥不因“记忆”一词进入同步。共享通用经验与项目私有知识仍要区分。

### 5.4 治理减负 ≠ 降级为收发文件

删除重复规则、反复签字、重复平台和低收益自研，不能把实际配置增强、工程任务执行协调、模型/上下文效率、成本与观测一起删掉。每次退役应指向已承接的原生/成熟能力或明确取消决定。

## 6. 原规划保留不等于复活全部旧方案

- 设计业务域迁出决定继续有效：WORK-LAB 不重新承接 DESIGN-LAB 的专业设计、资产、生成参数和质量业务。
- Open Design **客户端**的用户全局工作流/规则/插件适配，与 DESIGN-LAB **项目**的设计业务不同。固定 AGENTS 明确该区分；不能用早期“设计模块迁出”一句话删除后来恢复授权的客户端适配职责。
- MINIGAME 产品运行、发布、商业化不因“保留原规划”自动回到 WORK-LAB 活动模块。
- 不复活固定三方轮流治理、固定模型/推理档位、固定程序/版本/端口/路径，以及无需求的第二 Agent runtime、第二聊天 UI、全量私有会话库、模型代理网关。
- 历史 Radar 里出现过三项目适配评分、项目影响或 TaskPack 建议。长期监控回复继续服从用户后来的更新：中文、实质新变化/测评/测试，不恢复已取消的三项目分析输出。产品内按明确任务进行的能力研究与开源吸收仍可保留，不能混为同一种自动监控。
- 条件研究后置不是删除；历史研究清单里的每个项目或星级，不是自动采用或安装决定。

## 8. 历史任务的保留方法

沿用已有继承矩阵，尤其 H2/H3 已将旧 WL-000～WL-820 的主题对应到后续 WL3 任务。NX、WL3、WLR、NF 与 WL-R 的有效继承也需要保留，不从最近的20张 NF 父卡反推“历史已全部覆盖”。

这里只要求在**现有**任务表中保留：原任务ID/来源、原始职责、后续决定、现有承接项、已知证据、剩余范围。

状态含义应分开：
- 已完成：保留证据，相关变更时才做影响回归；不重做已修复内容。
- 保留待续：职责存在且有明确下一交付，不能只登记标题。
- 合并承接：说明功能实际落在哪一个既有任务/实现。
- 条件后置：写触发条件，不能变成永久消失。
- 明确取消/迁出：保留对应决定，不在本项目复活。
- 证据待补：不能当 DONE，也不能因旧机器账本缺失一律重开历史任务。

历史原文确有不完整处，先保留范围与线索、定点补证据；不要求每轮都把所有对话全量装进模型上下文。本次恢复的是总职责和专项从属关系，并非逐项最新运行审计。
