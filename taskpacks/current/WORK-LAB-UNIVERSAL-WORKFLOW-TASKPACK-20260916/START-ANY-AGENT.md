## 先做什么

读本项目实际适用的原生规则，接着读 `TASKS.json` 中 `NF-00-SYNC`，按依赖领取当前卡。只按需读取其它材料，不全量加载所有历史/技能。任务范围登记到**现有**账本，不启动第二套系统。

在本包目录，可用已有 Python 3.10+ 解释器执行 `python validate_taskpack.py --task NF-00-SYNC` 只提取一张卡；这是只读包内工具，不是新调度器。无需将整个 TASKS.json 灌进模型上下文。

第一批：NF-00-SYNC / NF-01-SYNC / NF-03-SYNC / NF-08-0。随后 NF-08-A、NF-08-B、NF-05-SYNC 可在不重叠工作树中并行；接通 NF-08-C/D 即交首条真实往返。再做 E/F/G/H/I、规则增强、Observer 和最终验收。允许设计与合成测试先行，真实副作用没有授权时只暂停该分支。

## 不得缩窄

不是只在 WORK-LAB 内跑；不是只连 ChatGPT↔Codex；不是必须 Hermes；不是必须 Git/GitHub；不是固定三个项目或七软件。共同机制共享，项目文件/任务/记忆/授权隔离。官方数据根不搬，用户模型/推理/认证选择不覆盖。当前软件真实缺口保留，不假装全支持。

## 实现原则

复用 TaskLedger、Telemetry、原 worker/runner、Adapter、Envelope/Capsule/Receipt 与只读 Observer。首通道为项目自己的 GitHub 位置，第二通道为不可变工件包适配；原生工具优先，不新造调度器、数据库、聊天 UI、更新器或全仓语言迁移。

保留旧修复，仅处理本卡差集。任务正文是用户选定的工件，不抓取私人聊天库；不得读取/复制凭据。跨项目文件只能在双方授权范围共享引用。Windows `E:\` 仍需每路径、每操作明确授权。

## 每卡交付

改动/复用点、测试或真实回读、结果级别、未完成项、恢复办法即可。源文件 PASS、模拟 PASS、真实客户端 PASS、精确 SHA CI 分开报告。M0/M1/M2 不是全部完成；最终至少两真实独立项目、两执行软件、两规划/查询入口、两环境、两通道、一个新增非 Git 示例，且支持矩阵有真实证据。

没有新权限/写入口时不要退回“生成 ZIP 算完成”；报告具体缺口，继续其它可执行卡。已经确证的授权范围内连续推进，不反复开启“全量再审计”。
