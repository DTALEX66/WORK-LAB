## Findings（按严重度排序）

### 🟡 Minor

#### CHK-01 · [copy] `覆盖 3/4` 没有名词，含义靠猜
- **出现位置**：`apps/observer/frontend/src/views/CompactHUD.tsx:186`
- **问题**：facts 行是「项目 4 · 覆盖 3/4 · rev 293」；前两项各有名词，中间一项只有分数。
  读者无法确定它指"项目 / 平台 / 采样"。同类问题也出现在 `覆盖 UNKNOWN`。
- **为什么不能直接改文案**：可见字符串被三处契约测试精确锁定
  （`compactHudPhenotype.test.tsx:136,187`、`renderTruthContract.test.tsx:149,157`），
  直接加"项目"会破坏真值断言。真值测试优先于文案优化。
- **修复建议**：保留可见字符串，在 `.hud-fact-line` 上加
  `title="覆盖：已报告 token 的项目数 / 项目总数"` 与 `aria-label` 同义说明；
  若要改可见文案，先同步更新三处测试，再改。

#### CHK-02 · [visual-hierarchy] 面板高度随状态跳动 57px
- **出现位置**：`apps/observer/frontend/src/skins/hud-phenotype.css:68`（`.hud-panel`）
- **问题**：六态实测面板高度 470–527px，底部边缘 573–630px。浮窗 `alwaysOnTop` 且无边框，
  高度随内容变化会让玻璃底边在桌面上"呼吸"，破坏设备感。
- **实测**：baseline 527 / many 523 / huge 470 / unknown 479 / zero 472 / stale 488。
- **修复建议**：给 `.hud-panel` 一个与 baseline 一致的最小高度（如 `min-height: 527px`），
  或把 footer 用 `margin-top: auto` 贴底；改完重跑 `verify-states.cjs` 六态确认 bottom 稳定。

#### CHK-03 · [components] 新增 CSS 用裸 rgba 阴影，绕过阴影 token
- **出现位置**：`apps/observer/frontend/src/skins/hud-phenotype.css:57`（`rgba(0,0,0,.3)`）、
  `:80`（`rgba(255,255,255,.05)`）
- **问题**：新 phenotype 层其余颜色都走 token / `color-mix`，只有这两处是裸值；
  亮色主题因此继承一个偏重的黑色 notch 阴影。
- **修复建议**：暗色用 `var(--shadow-soft)` 或定义 `--hud-shadow-notch`，
  亮色给同变量一个更轻的值；不要直接调透明度掩盖主题差异。

#### CHK-04 · [ia] 紧凑搜索退化为纯图标，发现性依赖 hover
- **出现位置**：`apps/observer/frontend/src/skins/hud-phenotype.css:323-332`、
  `components/layout/TopStatusBar.tsx:102`
- **问题**：440px 下搜索为 44×38 图标；`title` 与 `aria-label` 保证可访问名称，
  但视觉用户不 hover 就看不到「搜索或命令… Ctrl K」。这是布局取舍后的可接受退化，
  但仍是一个学习成本。
- **修复建议**：不扩大按钮（会再次挤爆 topbar）；在命令面板空态显示
  「搜索页面 / 命令 · Ctrl K」提示，把发现性放到用户已经打开面板之后。

1. **主题间总量不同不是主题差异**：dark 1,988,012（rev 293）与 light 2,012,012（rev 297）
   是两次运行之间 live sidecar 前进了 4 个修订。引用数字时必须带 rev。
2. **`overflow` 探针的差异**：`states-20261019e.log` 在 1.2s 采样点列出
   `ambient / action-sizer / ghost-btn ×5` 超出 440px；但同一页面 `doc.scrollWidth = 440`，
   截图中无可见溢出，说明这些节点被裁剪 / 不在可视层。baseline（6.5s）不列出它们。

   440×680 的结论适用于 web 层，窗口层仍是未验证项。
