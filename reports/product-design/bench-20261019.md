### 1.2 信息架构

- **竞品（usage 截图）**：分段控件（Tokens / Sessions）+ 时间 chip → 大总量 → 堆叠条 →
  逐 agent 卡 → 最近使用 → 热力图。这是**滚动优先的仪表盘 IA**。
- **WORK-LAB**：topbar（63px）→ notch → hero（总量 + 状态）→ facts（项目 / 覆盖 / rev）→
  3 张来源卡 → 份额口径注 → 会话 sparkline → footer（来源 + 时间）。这是**一屏优先的瞥视 IA**。
- **结论**：两者不是同一 IA 物种。照搬竞品的分段 + 热力图会把 440×680 变成需要滚动的
  小仪表盘，恰好破坏"HUD 一眼可读"的前提 → **不借鉴 IA，借鉴视觉层**。

### 1.3 交互模式

- 竞品：审批卡有 Allow / Deny（写操作）；usage 页有筛选 chip（具体行为截图不可判定）。
- 自己：布局切换（`完整` / `紧凑`，`TopStatusBar.tsx:148-150`）、Ctrl K 命令面板
  （`App.tsx:207`）、卡片 hover 抬升；**没有任何写操作**。
- **结论**：交互层是两种产品契约的分界线，不复刻。

### 1.4 内容策略

- 竞品：大数字 + 短标签，强结果感；截图中**看不到**来源、新鲜度、覆盖口径。
- 自己：`LIVE · 采样已过期`、`UNVERIFIED`、`份额 ≥26%`、`UNKNOWN`、`不按零相加`、
  `会话内采样，不是来源历史`——每个数字都带口径。
- **结论**：内容策略主动 **diverge**：竞品卖"看起来精确"，本产品卖"可审计的精确"。

### 1.5 无障碍（抽样，只能看静态图）

- 竞品的绿/红审批语义**同时**依赖颜色与文案（Allow/Deny 有文字），但截图无法验证对比度、
  焦点、键盘路径 → 记为 UNKNOWN，不作结论。
- 自己：亮色环从 1.93:1 修到 7.33:1（`hud-phenotype.css:20-31`）；12px 文本地板实测
  `tinyText: []`；`prefers-reduced-motion` 下脉冲/抬升/弧线/眼睛全部关闭
  （`hud-phenotype.css:400-405`）。

## 3. Castle vs Shack

### 🏰 结构性壁垒（绕开走，别硬刚）

- **可执行审批闭环**：Allow / Deny 需要写权限、状态机与审计链；Observer 的契约是
  read-only projection（`AGENTS.md`：「must not execute, approve, retry, apply…」）。
  复刻它不是设计选择，是越权。
- **采集与聚合管线**：竞品的仪表盘形态依赖按桶历史数据；本仓 v3 快照只有"当前总量 +
  修订号 + 会话内采样"。没有数据源就画热力图 = 伪造。
- **公开 OSS 分发与品牌**：与内部只读控制台不同赛道，不比较。

### 🏚️ 可借鉴的表层优势

- notch / 玻璃 / 顶部辉光 / 环形进度 / 大号 tabular 数字 / 会话 sparkline /
  指针跟随的眼睛 —— 全部已落地并用几何实测验证。
- "逐来源卡片"的信息组织 —— 已落地为 3 卡 + 聚合卡。
- 悬停抬升的微反馈 —— 已落地，且带 reduced-motion 降级。

## 4. 视觉策略决策

**选择**：`diverge`（视觉身份差异化；phentotype 表层 lean-in）

**理由**：notch / 玻璃 / 环是品类语言，沿用能降低理解成本；但身份必须靠三件事区分：
① 只读、无动作按钮；② 数字永远带口径（UNKNOWN / ≥ / 采样过期）；③ 亮色主题用
ink-safe 青而不是霓虹青。三者叠加后，用户看到的不是一个"能点的玩具 HUD"，而是一个
"可以信的仪表"。

**行业视觉地图**：agent-hud-open（深色霓虹玻璃）、Linear（极简高对比）、
Vercel Dashboard（黑白 + 单一强调色）、Datadog（高密度图表）、Grafana（可配置面板）。
本产品取 Linear 的克制 + 竞品的玻璃质感，拒绝 Datadog/Grafana 的密度。

## 5. Takeaways（按 action 分组）

### ✅ Borrow（已借鉴并落地）

#### 🥇 T1 · notch + 玻璃 + 顶部辉光
- **来源**：usage-statistics.webp 顶部
- **落地**：`.hud-notch`（165×26）、`.hud-panel` 径向高光、`.hud-top-glow` 2px 渐变
- **3 问**：为什么 work——把浮窗锚定成"设备"而不是普通窗口；上下文匹配——yes，Tauri 无边框浮窗；
  副作用——辉光若挂在被 mask 的元素上会被裁掉，故放在未 mask 的兄弟节点。

#### 🥇 T2 · 环形来源份额 + 指针跟随的眼睛
- **来源**：usage-statistics.webp 的 agent 卡
- **落地**：3 环；`hud-ring-arc` 空份额改为 `butt` 端帽（零长度弧不再画一个假点）
- **3 问**：为什么 work——环让"份额"在 12px 文字之外多一个可扫的形状；上下文匹配——yes；
  副作用——纯图形对比度不足，亮色改用 7.33:1 的 ink 青。

#### 🥇 T3 · 超大 tabular 总量
- **来源**：usage-statistics.webp 居中大数字
- **落地**：41.8px；18 字符时降到 23.3px，实测盒宽 236px 无横向溢出
- **3 问**：为什么 work——瞥视第一落点；上下文匹配——yes；副作用——超长数字会撑破 440px，
  已用自适应字号封顶（min 22px）。

#### 🥇 T4 · 会话 sparkline
- **来源**：usage-statistics.webp 的趋势区
- **落地**：只画**本次会话**的不同修订；<2 个修订显示"序列未形成"空态，不补点
- **3 问**：为什么 work——给出方向感而不冒充历史；上下文匹配——partial，数据只有会话内；
  副作用——用户可能误读为来源历史，故副标题明写"会话内采样，不是来源历史"。

### ❌ Avoid（明确回避）

#### A1 · Allow / Deny 审批动作
- **来源**：approvals.webp
- **为什么是坑**：Observer 是严格只读投影；加动作会把审计面变成授权面，违反
  `AGENTS.md` 的 Workflow Assistance 契约。审批请留在 Workflow/回执侧，Observer 只展示证据。

#### A2 · 用绿/红辉光表达"可执行"
- **来源**：approvals.webp 的绿/红边缘光
- **为什么是坑**：本产品的绿/红只表达**状态**（live / offline），不表达**动作**；
  颜色也不能单独承载信息（`data-state` + 文案同时存在）。

#### A3 · 把密集仪表盘塞进 440×680
- **来源**：usage-statistics.webp 的整体密度
- **为什么是坑**：紧凑 HUD 的 KPI 是"3 秒可读"；分段控件 + 热力图 + 多行卡会引入滚动。
  实测一屏内容 617px，已经刚好填满；密度请留给完整视图。

### 🟰 Match（行业标配，保持）

- 深色玻璃、tabular numerals、hover 抬升、状态点脉冲（reduced-motion 关闭）。
- 大数字下方给出单位与质量口径，而不是只给一个百分比。

### ⏸ T5 · 分段 / 时间 chip / 热力图（本轮不做）

- **3 问**：为什么 work——竞品有按桶历史，能讲"什么时候用的"；上下文匹配——**no**，
  v3 快照没有按日/按桶真值；副作用——画出来只能是假数据。**结论：等数据源，不先画 UI**。
