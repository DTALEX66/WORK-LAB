# Pitch — 下一轮的 HUD 决策与 Asks

- **生成时间**：2026-10-19
- **对象**：项目 owner（唯一读者、唯一决策者）
- **目的**：把本轮"已做 / 未做 / 要你拍板"压缩成一页

## 1. The Bet

**我们押注：一个 440×680、能在 3 秒内被信任的瞥视面，比一个看起来精确的密集仪表盘更有价值。**

理由不是审美，而是产品定位：Observer 是只读投影，用户拿它做"是否要调查"的判断。
判断的敌人不是信息少，而是**假精确**——过期采样显示成 LIVE、未知写 0、0/0 画成 0%。

## 2. Why Now

本轮已经把真值层补齐，且都有实测回执：

- 过期采样：`LIVE · 采样已过期` + 琥珀 + `data-state=waiting`（141px 胶囊，不换行）。
- 未知 / 零：`UNKNOWN`、`份额 —`、`0` 三者分开；零份额环不再画假点。
- 多来源：9 源折 3 卡（11% / 11% / 78%，`其他 7 个来源`），面板仍不滚动。
- 超长数字：18 字符 23.3px，盒宽 236 = 文本宽 236，无溢出。
- 亮色：霓虹青 1.93:1 → ink 青 7.33:1。
- 一屏：content 617/617，topbar 63 单行。

这些是"可被引用"的基线；现在缺的是**窗口层复测**与**交互收尾**，不是再换一套视觉。

## 3. User + JTBD

**单人运维者**：自管 Agent 队列的仓库所有者，同时是操作者、审计者与唯一读者。

> 当我扫一眼浮窗时，我想在 3 秒内判断这个数字可不可信、是谁在用，
> 以便决定是否切到完整视图调查——而不是被一个看起来精确的假数字误导。

（注：本轮**没有**做用户访谈；这是由契约与实测推导的 JTBD，不是研究结论。）

## 4. Direction

**借鉴表型，拒绝动作面。**

- 借鉴：notch、玻璃、顶部辉光、环形份额、指针跟随的眼睛、大号 tabular 数字、会话 sparkline。
- 拒绝：Allow / Deny 审批（越权）、绿/红动作语义（颜色只讲状态）、
  分段 + 热力图塞进 440px（需要滚动，且无按桶真值）。
- 差异化：只读、口径化数字、亮色 ink-safe。

## 5. Design Decisions（每条带证据）

| # | 决策 | 证据 | 代价 |

| D1 | 9 源折成 3 卡，末卡为聚合 | `摘要 3/9`、`其他 7 个来源`，面板 bottom 626 | 个体要切完整视图 |

## 6. Asks（需要 owner 拍板）

1. **授权下一轮做真实 Tauri WebView2 440×680 复测**（headless Chromium 不能证明窗口层字体/合成）。
   需要拉起一次真实窗口；这是本轮唯一必须开界面的项。
2. **F-04 / F-03 / F-02 是否直接修**：面板最小高度、命令面板空态提示、`覆盖` 行 title/aria。
   三项都不改真值字符串，风险低。
3. **F-01 来源卡深链**是否进入下一轮：它把"其他 7 个来源"变成可追，但需要完整视图支持
   按 provider 定位，属于新增交互。
4. **提交与推送授权**：当前改动未 commit / 未 push；是否本轮收口。

## 7. 不做清单（防止范围漂移）

- 不做热力图 / 堆叠条 / 分段控件（无按桶真值）。
- 不做审批 / 重试 / 应用动作（只读契约）。
- 不做移动端（契约外）。
- 不为 `apps/token-monitor` 原型继续加功能，其去留待单独决定。
