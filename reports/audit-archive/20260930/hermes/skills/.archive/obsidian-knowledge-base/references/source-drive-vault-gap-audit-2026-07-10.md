# 源盘—Vault 映射与用户要求差距审计（2026-07-10）

## 适用场景

用户要求“全面审计 Obsidian vault 与源盘映射和用户要求差距”，且明确要求：

- 源盘只读；
- 不运行重型 OCR / ASR；
- 检查课程数量、`source_root`、基本页、空白/乱码/水印、历史归档和错误合并；
- 不接受仅凭目录/主页存在就宣称“100% 完成”。

## 已验证的审计方法

### 1. 先建立两个不同的覆盖口径

不能把“课程目录已映射”当成“源文件已处理”。至少分别报告：

1. **目录级覆盖**：源盘二级课程目录是否被某个正式课程 `source_root` 精确或祖先级覆盖。
2. **文件级显式追溯覆盖**：源文件名或相对路径是否在对应课程 Markdown 中出现。

文件级指标只是保守代理，不等同于语义处理率，但能阻止无证据的 100% 声明。若需要可信的完整覆盖率，必须建立逐课程 manifest/ledger，记录每个源文件的识别、抽取、核验和过滤状态。

### 2. 正式课程识别

优先用正式课程区中的 `00_课程主页.md` 识别课程，而不是简单统计所有 `C####_*` 目录；附件、历史备份、关键帧目录也可能带课程 ID。

同时分开统计：

- 本地源课程（主页中有 `source_root`）；
- OER/开源课程（没有本地 `source_root`）；
- 聚合课程（`source_root` 指向整个类别根）；
- 重复或游离课程 ID。

### 3. `source_root` 审计必须做四向一致性检查

对每个课程比较：

- 主页 `source_root`；
- `source_link`；
- 正文“原始路径”；
- 素材报告中的“来源目录/核验来源”。

单独检查每条路径是否真实存在。常见问题是 `source_root` 已迁移到新盘结构，但素材报告和正文仍保留旧分类架构。

### 4. 检查 metadata 是否真的是 frontmatter

仅出现：

```text
title:
status:
source_root:
```

不代表 Obsidian Properties 可用。必须确认文件以 `---` 开头且有闭合 `---`。否则 Dataview 无法可靠读取状态字段。

### 5. “100% 完成”冲突检测

查找主页中的 `完成度: 100%` / `100%正式入库`，再与以下词语交叉检查：

- 待转化、待整理、待生成；
- 未转写、未核验；
- 仅建立目录；
- 不代表已完成全文核验。

推荐把完成度拆成独立字段：

- `mapping_status`
- `inventory_status`
- `extraction_status`
- `verification_status`
- `learning_assets_status`

禁止用一个 100% 同时代表映射、转化、核验和学习资产完成。

### 6. 基本页完整性

使用当前项目约定的最低集合检查每门课程：

- `00_课程主页.md`
- `00_课程总览.md`
- `01_素材识别报告.md`
- `07_实操工作流.md`
- `08_术语索引.md`

必须分别报告本地源课程与 OER 课程完成率，避免结构完整的 OER 课程掩盖本地课程缺页。

### 7. 链接与 Dataview 检查

至少检查：

- wikilink 目标能否按 vault-root、当前目录或 basename 解析；
- 图片 embed 是否存在；
- 旧根路径（例如迁移前课程库/知识卡/复习卡目录）引用次数；
- `FROM` 查询是否指向当前正式路径；
- `TABLE` / `FROM` 是否处于合法的 ````dataview` fence 中；
- 文件中三反引号数量是否为奇数。

静态链接检查可能包含少量 Obsidian 模糊解析差异，报告时标注“静态保守检查”；但不存在的旧根路径和明确损坏的代码围栏属于确定问题。

### 8. 空白、乱码、水印应分开报告

- 空文件：按文件大小 0 检查；
- 极短文件：作为待审清单，不能全部判为错误；
- 编码损坏：优先检查 `U+FFFD`；
- OCR/ASR 噪声：即使没有 `U+FFFD`，也可能存在无意义字符、下载按钮、群号等内容级垃圾；
- 水印/推广：检查资源网站名、网购返利、免费下载、QQ群、微信、扫码等。

不要把“OCR 垃圾”误报为“UTF-8 编码乱码”。

### 9. 历史归档与错误合并

- 对 `待人工合并`、`原始逐节总结备份`、`历史误合并产物` 分别盘点；
- 检查通用文件名下是否塞入了某门具体课程内容；
- 检查正式区是否存在同一课程 ID 的游离目录；
- 计算历史备份与正式文件的精确 hash 重复，但 **0 个精确重复不代表归档全部有价值**，只代表不能安全按文件名批量删除。

课程合并必须按课程 ID + `source_root` + 内容来源共同判断，不能只按文件名或领域名自动合并。

### 10. 审计快照稳定性

长审计前后重新统计 Markdown 数量及关键归档目录。如果数量或目录结构变化，说明同步工具或其他代理正在写入：

- 明确声明审计不是静止快照；
- 以最后一次扫描为临时口径；
- 整改前先冻结并发写入并重跑基线；
- 不在变化中的 vault 上执行批量合并/删除。

## 本次审计暴露的典型模式

- 课程主页数量与源盘二级目录数量相同，并不表示一一对应；其中可能混有 OER、类别聚合和重复源目录。
- 所有主页都可写有“100%”，同时多数正文仍是“待生成”；完成率必须来自可验证阶段字段。
- `source_root` 可以真实存在，但 `source_link`、素材报告和核验说明仍指向旧盘结构。
- 旧路径迁移后，Dataview、wikilink、图片相对路径和报告正文可能同时漂移。
- 历史目录可能已明确标记“误合并”，应视为隔离证据，不应再次自动吸收。
