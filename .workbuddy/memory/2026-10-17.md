## ⚠️ 一次险情（must-read，含恢复步骤）

**现象**：工作区突然出现一批我从未改过的文件被修改/冲突——`config/config.yaml`、`config/managed-config-schema.yaml`、
`docs/current/workflow-assistance-*.md`、`docs/current/workflow-assistance/**`（6 个，其中 4 个含 `<<<<<<<` 标记）、
6 个 skills 引用文件、`docs/history/archive/.../error-fixes-2026-07-04.md`。**同时写者的 4 个文件从"已修改"变成"无变化"。**

**两个真实原因（都不是"别人在改"）**：
1. 我在 W07b 用了 **`git add -u docs/ taskpacks/`** —— 它把**工作区里所有被改动的跟踪文件**（包括并行写者的在途改动）
   扫进了**我的**暂存区；随后切分支/弹 stash 让它们变成冲突。
2. 用户 **2026-10-07 自己 park 的 stash**（`live-doc-repoint-discard-me`，35 个文件，含 `config.yaml` 与那批 docs）
   被卷进了我的工作树 —— 它名字里就写着 discard-me，**不该进任何提交**。
   我用 `git stash show --name-only 9d393d9f` 认出它，并把它的文件逐个 `git checkout HEAD --` 还原。

**恢复步骤（可复用）**：
- 写者文件的**权威基准**是 `.project-local/runs/writer-files-before.txt`（sha256）。用
  `git fsck --unreachable --no-reflogs | grep commit` 找出被 drop 的 stash 对象，逐个用
  `git show <stash>:<path>` 取内容并**比对 sha256**，取 4/4 匹配的那份 `git checkout <stash> -- <paths>`。
  本次 6 个 stash（merge-main-isolate / inv-isolate / w07-merge-main / rebase-isolate / rebase-isolate2 / w09-move-to-main）
  **全部 4/4 匹配**，内容完好，最终 `sha256sum -c` 四个 OK。
- **反例（我自己又踩的）**：恢复循环里我按"旧 stash 的 35 个文件"逐个 `git checkout HEAD --`，
  而 `AGENTS.md` 与 `config/adapter-registry.json` **也在这个列表里** → 把写者那两份打成 HEAD，第一次 `-c` 报了 2 FAILED；
  再从核验过的 stash 取回即 OK。**教训：还原一个文件集之前，先把它与"写者的权威清单"取交集排除。**

**新规矩**：
- **永远不要 `git add -u <dir>`**；只按显式路径 `git add`（本会话前面一直这么做，这次图省事就出事）。
- `git stash push -u` 会把**整棵树**（含别人已暂存的内容）capture 进去，弹出时冲突会**传播出冲突标记**；
  隔离并行写者只用**显式路径**的 stash（本会话多数时候如此）。
- 发现"我从未改过的文件被改了"时，**先查 `git stash list` 里有没有别人的/自己的旧 stash**，再决定动手。
