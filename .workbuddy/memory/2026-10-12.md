### 门全红的真正原因（产品缺陷，不是环境）
`integrations/executors/codex/install_codex_global_guidance.py` 在 Windows 上：
打删除挂起标记的 SetFileInformationByHandle 返回 WinError 24 → 异常被打印后吞掉 →
仍然打印 `CODEX_GUIDANCE_WRITTEN` 并退出 0，而 AGENTS.md 不存在。
且该处置单向不可撤销，发布路径却依赖「发布前清除」。改为完全不用删除处置：
私有性靠 CREATE_NEW + 128 位随机名 + FILE_SHARE_READ，发布仍是同一个原子 FileRenameInfo，
放弃时按名删除；`st_nlink` 在 Windows 期望值由 0 改 1（多一个即硬链接攻击）；发布后覆盖竞态改为按名撤回。
结果：该模块由 origin/main 基线 15 failed / 79 passed → 2 failed / 91 passed。

### 环境上限（不是产品红灯）
宿主 CLI 的 `sitecustomize.py` 代理了 `os.symlink` 与 `os.link`，建出来的对象
`is_symlink()` 为 False、`lstat` 无 REPARSE_POINT → 依赖真实链接的用例无法构造前提。

### 边界外溢的教训
直调 pytest 会继承 shell 的 `TEMP=C:/Windows/TEMP`，而只有 `run_quality_gate.py` 会把它
改写到 `.project-local/runs/tmp`。已加封装 `.project-local/runs/wui-20261012/run-pytest-in-project-temp.sh`。
