# OpenViking 上下文服务标准（部署 / 治理 / 管理）

状态：生效
落定日期：2026-10-24
适用：WORK-LAB 涉及「跨会话记忆、上下文检索、多客户端接入」的所有工作
配套操作手册：`docs/decisions/OPENVIKING_DEPLOY_HANDBOOK_20261024.md`

---

## 1. 定位与非目标

本服务是 WORK-LAB 的**外部上下文基础设施**，不属于本仓代码，不改变本仓的授权链、任务账本或模块边界。

- 纳入：会话记忆抽取、语义检索、资源入库、多客户端接入配置。
- 不纳入：业务执行、任务调度、UI 呈现。本仓不因接入它而扩大开发范围。

## 2. 拓扑与端口契约

| 项 | 值 | 约束 |
|---|---|---|
| 服务端口 | `127.0.0.1:1933` **唯一** | 不得为新增客户端另开端口 |
| REST / MCP / Studio / 网关 | `/api` `/mcp` `/studio` `/gateway` | 同端口不同路径 |
| 向量维度 | 1024 | 与集合维度必须一致，变更需重建并归档旧数据 |
| 模型出口 | VLM 远程、Embedding 本地 | 换模型属治理变更，见 §5 |

端口、维度、模型三者任一变更，都会使既有索引不可用，**必须按 §5 走变更流程**。

## 3. 接入矩阵与自动化等级

| 等级 | 含义 | 客户端 |
|---|---|---|
| A 全自动 | hooks 自动召回 + 捕获 + 提交 | Claude Code、Codex、Cursor、TRAE CN、Qoder CN、DSH |
| B 半自动 | MCP 可用，捕获需一次配置 | Hermes |
| C 手动 | 仅 MCP，模型主动调用才有记忆 | CodeBuddy、MiniMax Code、WorkBuddy |
| D 不可接入 | 无 MCP / hook / 自定义端点 | 豆包 App、设计类工具、ComfyUI、Grok Bot、供应商切换器 |

判定接入方式时**先看客户端能力，再看产品**：同一产品不同入口（IDE / CLI / 桌面）能力不同，不得一概而论。

## 4. 配置所有权

| 内容 | 归属 | 规则 |
|---|---|---|
| 服务端配置 `ov.conf` | 本机运维 | 含模型与维度，属受控变更 |
| 客户端连接 `ovcli.conf` | 本机运维 | `url` 必须显式写入，不依赖默认值 |
| 各客户端 hooks/MCP 配置 | 各客户端自持 | 只做最小注入，不接管其全量配置 |
| 插件源码 | 稳定目录 `~/.openviking/openviking-repo` | 不得指向临时下载目录 |

凭证一律不落文档、不进仓库；发现泄露只登记位置与风险类型。

## 5. 变更协议

任何一项变更（端口 / 模型 / 维度 / 插件版本 / 新增客户端）必须：

1. 记录变更动机与影响面（哪些客户端、哪些索引失效）。
2. 备份将被改写的配置与数据目录。
3. 先在单个客户端验证，再推广到其余客户端。
4. 用 §6 的验收项闭环，不以 `health` 成功替代功能验收。
5. 回滚路径明确（备份路径写入提交说明或运维记录）。

禁止：静默升级、静默换模型、绕过官方安装方式手改第三方应用数据库、为省事关闭鉴权。

## 6. 验收门（缺一不可）

| 门 | 判据 |
|---|---|
| 服务 | `/health` 返回 `healthy:true` |
| 协议 | MCP `tools/list` 返回预期工具数 |
| 检索 | 一次真实查询命中并给出分数 |
| 写入 | 一次真实写入落库并可读回 |
| 自动化 | 目标客户端在**新会话**中实际调用检索与读取工具 |
| 归档 | 抽取产物出现在预期记忆路径 |

「配置文件已写入」不等于「客户端已生效」；「服务健康」不等于「工具可用」。二者必须分开验证。

## 7. 已知失效模式

| 现象 | 根因 | 处置 |
|---|---|---|
| 客户端工具列表为空/被移除 | 服务端未运行，MCP 握手失败 | 先起服务，再开新会话或重连 |
| 目录页 404 | 客户端连的是别的服务或错误分组入口 | 核对基址与分组，不以产品名假定地址 |
| 启动即报维度不一致 | 索引维度与配置不符 | 归档旧数据后重建 |
| 归档导入全部失败 | 客户端与服务的版本字段不兼容 | 记录版本对，等对齐后重跑，不做半成品绕过 |
| hooks 不触发 | 未信任或客户端不支持 | 信任一次；不支持的客户端降级为 C 级 |

## 8. 记录纪律

- 结论进标准，过程进手册，一次性排障细节进历史档案，三者不混。
- 标准只写**稳定约束**；易变的版本号、命令、错误码放手册。
- 每条结论标注证据来源（命令输出、日志路径），不写「应该可以」。
