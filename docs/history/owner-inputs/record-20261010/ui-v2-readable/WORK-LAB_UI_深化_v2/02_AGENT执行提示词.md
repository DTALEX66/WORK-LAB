# 交给执行 Agent

请在当前 WORK-LAB 检出中实施本包 UI 深化 v2。先完整阅读 `00_先读我.md`、`01_深化实施任务书.md` 与 `inputs/UI_v1任务书_只读快照.md`，并核对仓库当前 AGENTS、权威、CURRENT、OPEN、合同和生成源。本轮只深化 UI 可落地性，保留既有产品边界、技术栈与确认的品牌资产。

1. 先检查实际源码与读/写接口，把 `docs/03_接口绑定矩阵.csv` 填为真实合同、字段路径、源码位置、未知处理与证据；不要创造端点或将示意类型建立为新权威。合同缺少时分清需要仓库补齐的服务与前端可先完成的部分。
2. 复用现有组件完成真实响应式布局。参考 `prototype/index.html` 的表单与状态探索，但不能复制演示权限、内存状态机、默认样例数据作为生产行为。按源组件生成界面，不用PNG/SVG整页代替组件。
3. 按任务书P1–P3依次完成：首页/详情与多项目身份、能力导入预览及评价、用户目标选择、隔离试用/目标验证、发布/读回/行为/恢复、首次接入及规则限定合并。普通按钮要连接具体操作或详情；无资格或无合同显示真实原因。
4. 所有写入使用现有后端授权、限定范围、前态版本/摘要、幂等与过期合同。遇并发编辑保留用户现态，重读和重预览。计划身份变化使旧验证失效。取消或刷新不能造成重复写入。
5. 按 `docs/05_验收清单.csv` 实测并填写。测试仓库要求和变更相关行为；增加有意义的守恒、并发/恢复和身份测试，不以重复实现的快照代替验证。留下浏览器和原生壳证据；不能将包内模型测试算为实机通过。
6. 同源更新必要的导航断言、生成投影与消费点；旧任务/执行/证据仍定位原身份并保留权限和错误。消费者迁移后再归档。不要删掉旧保护断言来制造绿灯。
7. 结束提供具体可评审代码、接口矩阵、实际截图、验证报告、未完成项及原因。区分“设计完成”“前端实现”“后端接通”“实机验证”“部署”。用户既有授权继续有效；不凭本包扩大到全局客户端覆盖、其他项目写入、通信或发布。
