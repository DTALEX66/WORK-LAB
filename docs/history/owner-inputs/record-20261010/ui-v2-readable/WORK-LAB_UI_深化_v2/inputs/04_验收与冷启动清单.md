## 冷启动审阅

在干净工作目录或明确隔离上下文中，仅从仓库默认入口及其现行引用读取。记录阅读路径和实际回答。已有独立只读审阅安排时由其执行；本包不要求擅自启动更多并行写者。

| 必答问题 | 合格回答 |
|---|---|
| 默认监控什么？ | 项目运行摘要；详细诊断按需，不全量任务正文 |
| 谁执行业务？ | 外部AI软件，不强制经过WORK-LAB派工 |
| 能力资产价值？ | 好用能力评价、中立适配、选定目标验证与版本维护 |
| AAOS是什么？ | 完整知识、人的研究学习、AI学习资产、双向学习与长期记忆 |
| DESIGN-LAB能有内核吗？ | 能有设计专用内核，专业作品和验收归它 |
| 三方必须每次联合吗？ | 否；直接/双边/多方按需；独立产品验收发布 |
| Observer能做什么？ | 正常只读交互，不能越权改业务；获准写走独立边界 |
| 未来任务怎么算？ | 保留条件、范围与未实现；延后/替代不计为实现 |
| exit0或文件存在意味着什么？ | 只是运行/产物信号，还需合同要求的内容和接受证据 |
| 已接收候选意味着可信吗？ | 不意味着；知识治理与授权/技术/设计/学习状态独立 |
| 旧资料如何读取？ | 历史证据可查，不会默认重新授权当前任务 |
| 本轮到底完成了什么？ | 依据实际差异、测试、读回与版本回答，不能用任务包存在证明 |

机器验证结构/引用/权限/版本/行为；语义审阅按上述问题记录证据。关键词只发现候选，否定句和历史引用不自动判违规。目标是可发现可纠正漂移，不承诺永久零漂移。

## 结果记录
