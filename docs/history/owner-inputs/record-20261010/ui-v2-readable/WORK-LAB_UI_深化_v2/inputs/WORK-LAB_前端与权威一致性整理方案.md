## 2. 本次必须保留的产品决定

1. 以项目为监控主体。观察参与软件、活动、主要阻碍和资源汇总；默认不记录全部任务步骤、提示词、工具参数、返回正文及子Agent轨迹。
2. 允许读取归属、计量和去重所需的最小事件；按需诊断仅针对选定项目、问题和时间范围。后台采集范围也必须收敛，不能只是前端隐藏详情。
3. 外部AI软件执行项目。WORK-LAB可提供明确委托的协调、环境、权限、预算、并发和恢复支持，不强制每项工作经过本产品，不把未建通用派发器视为监控首版必然阻塞。
4. 个人能力资产的核心是筛选和迁移复用：源软件使用评价 + 用户判断 + 可迁移性评估 → 最小中立化 → 用户选择目标 → 目标验证与版本维护。安装数和调用数不等于有效性。
5. AAOS是完整的本地优先知识与人机双向学习系统，包括人的知识工作/研究/深度学习、共同知识基础和AI学习资产。长期知识与项目记忆由AAOS管理，不缩成机器上下文服务。
6. 跨软件项目接续未来按需从AAOS获取关键项目事实/决定并核对当前现场；不复制全部聊天历史，不成为当前独立监控的前置条件。
7. DESIGN-LAB拥有专业设计判断、原生作品与设计专用执行内核；它也能使用外部软件。WORK-LAB不接管其专业状态，二者无需每次经第三方才能协作。
8. WORK-LAB既使用获准知识，也可从选定真实工作中提炼带来源、反例、限制的候选交AAOS。候选接收、知识认可、技术通过、设计验收和真人学习评价分开。
9. 技术经验 → AAOS知识与学习目标 → DESIGN-LAB教学表达 → AAOS人的学习 → 各责任方反馈改进，是可选长期协作路径。不能据此新增通用教学平台、知识库或学习状态写者。
10. Observer不修改业务权威；筛选、搜索、复制、展开等纯界面操作不因此禁止。获准配置/资产操作走独立命令边界，不以隐藏按钮替代权限校验。

## 4. 前端目标：结构收敛，不先换皮肤

推荐五个主要目的地，设置保留低频位置：

| 目的地 | 主任务 | 默认不做 |
|---|---|---|
| 项目监控 | 项目活动、参与软件、主要阻碍、资源摘要 | 全量任务树、逐请求轨迹、猜测项目完成率 |
| 软件与环境 | 软件支持范围、接入健康、更新影响、规则加载情况 | 复制IDE或所有客户端内部管理功能 |
| 能力资产 | 来源与评价、中立适配、选定目标、验证与发布维护 | 只有安装/调用排行榜，自动覆盖所有客户端 |
| 用量与缓存 | 项目/软件汇总、单位和质量说明、必要对账 | Token/Credits乱换算，累计值重复相加 |
| 规则与适配 | 规则映射、生效、漂移、授权变更与恢复 | 通用任务审批总中心或另一套知识治理 |

“项目监控”承担总览和项目入口，不另建内容重复的总览与项目两套首页。软件视角仍可查看参与项目。
三方协作置于相关项目/问题/能力详情中的协作区：候选发送、接收回执、教学引用、技术检查和反馈。不是第六个知识或学习主平台。
工作流画布、执行详情、证据区间等保留有价值实现和旧深链，迁为按需诊断、兼容入口或实验功能。不能把所有旧页面都强行塞进五组来宣称收敛。

更名与导航调整要同时核对 App、registry、sidebar、command palette、deep links、read models、采集默认值和相关测试。UI不应只是把详细监控藏起来。
视觉保留可用的品牌资产、组件、主题与无障碍基础；只有真实使用问题才改，避免以另换整套UI作为前置工程。

## 5. 文档角色、生命周期和实现状态分开

建议沿用现有CURRENT/SUPERSEDED/HISTORICAL/DEFERRED等状态，不另造平行注册系统。若字段不足，最小扩展原Schema并保留兼容读取。
三个独立问题：
- 文档角色：规范、计划、证据、生成投影、参考。
- 适用性：现行、未来/延后、被替代、历史。
- 实现证据：计划、源码已有、受控测试、真实运行、人工接受、发布。
日期、标题里的FINAL/CURRENT/COMPLETE、生成成功或commit数量，都不能自动决定后三者。

处置策略：
1. 现行规范且语义冲突：原位修订权威源，记录被替代条款；必要时版本化发布。
2. 仍有效的安全边界、工程行为、恢复方法：保留，不因为年代旧就归档。
3. 已完成的一次性交接和旧审计：移到既有历史体系，保留源SHA和历史角色。
4. 未来能力：DEFERRED，保留重启条件，不计入首版完成率。
5. 仍被运行器/生成器/测试读取的旧文件：先登记依赖并迁移消费者，必要时保留最薄兼容入口，不能直接移动。
6. 无法确定归属或含用户内容：只登记、待复核，不归档或删除。
7. 同字节重复文件：先验证字节及依赖，再归并入口；保留来源关系。相似正文或相同标题不能直接判重。
8. 签名、哈希或发布绑定的历史证据：保留原字节，纠正信息写在旁置元数据/替代记录，不能给原件加横幅导致哈希失效。

## 6. 归档流程：先摘掉指令效力，再迁移路径

发现精确文件 → 识别现行引用与历史引用 → 判断剩余有效条款 → 更新源定义与消费者 → 制作可恢复保留点 → 迁移或历史标记 → 更新索引/生成器/深链 → 校验 → 人工核对。

现行规范引用旧“证据”是允许的；现行任务偷偷引用旧“执行指令”是不允许的。校验必须区分引用角色，不能粗暴禁止出现 history 字样。
引用检查不只覆盖Markdown链接，还要覆盖JSON/YAML字段、importlib/脚本字符串、CI和测试夹具、上下文生成器、Agent技能与Hook、索引器和默认检索清单。

归档目录里带AGENTS.md/CLAUDE.md/SKILL.md等可被工具自动加载的文件，应测试实际加载行为：可以采用不自动发现的路径/扩展名和封装副本，并保留原字节及映射；不能只依赖一句“非权威”横幅。
如果文件路径被工具契约、签名或外部引用锁定，先保留兼容入口并登记退出条件，不强行全库搬迁。

旧客户端本地投影、工作树缓存、桌面启动文案、Project附件、Library报告和其他已分发包，属于“仓库之外的副本”。仓库修订不会自动更新它们。按来源登记，获准后定向重生/替换；未访问不得宣称已清理。不要清空全局记忆、客户端数据库或全库重建索引。

2. 项目以项目汇总为默认，原生软件直接启动也能被既有支持路径观察；不因整理强制采集完整任务内容。

4. 能力中心具有来源评价、目标选择、适配损失、目标验证和版本关系，不只展示调用数。
5. Observer不越权，已获准配置治理继续正常；不把安全保护通过“删测试/扩大授权”解决。
6. 候选可在合法范围提交但不自动可信；本轮只改变合同不应宣布AAOS真实接入。
7. 上下文/状态/技能生成器从新的源重生后再次执行无未解释漂移；生成投影的时间戳变化不能充当重新测试。
8. 普通冷启动上下文不包含已替代的可执行旧指令；指定读取历史问题时仍找得到证据。
9. 由独立只读审阅者仅用默认入口回答：项目监控还是全量任务？能力迁移还是调用统计？谁管知识/人的学习？谁管设计执行？哪些是未来？答案需与显式决定一致。

11. 对全量扫描范围给出eligible/scanned/skipped/reason，不能用一次grep无命中宣称不存在语义漂移。
12. 本方不自动修改AAOS/DESIGN-LAB、原生客户端、外部数据根，不安装/推送/发布。

关键词检查只能找候选，不能把“这里不是总控制器”中的总控制器词样当成违规。机器验证结构、依赖、状态和行为；自然语言语义仍需有范围的审阅。不能宣称永久零漂移。
