# WORK-LAB UI 深化实施任务书 · v2

目的：把已有视觉母版深化为用户能理解、执行和恢复的前端。保留蓝色专业工作台、中文优先、深浅主题和现有技术栈。具体操作不能停留在解释弹窗；成功、失败、等待与冲突有真实数据依据。

## 1. 实施顺序与完成标准

| 阶段 | 工作与交付 | 进入下一阶段的条件 |
|---|---|---|
| P0 合同核对 | 检查当前仓库权威、导航、组件、读取合同、命令合同、真实入口；填接口矩阵 | 每个字段有来源与未知处理；每个写操作有真实资格、范围和并发合同 |
| P1 阅读与布局 | 自适应壳、项目/软件摘要、三轴状态、来源时间、搜索过滤、空/错误/过期数据 | 多项目身份不串；字体不整体缩小；旧对象路由保持身份和权限 |
| P2 能力闭环 | 导入预览、来源评价、目标选择、损失说明、隔离试用、目标验证 | 来源/目标/适配器/范围/方案版本变化会使旧证据失效；失败可定位和重试 |
| P3 原生配置治理 | 首次接入、规则三方比较、发布/加载/行为分开、限定恢复 | 后端鉴权与幂等实际通过；用户并发编辑保持原样；恢复范围不会越界 |
| P4 实机验收 | 浏览器与原生壳，DPI、IME、真实样例、数据增长和资源实测 | 清单中生产阻断项均有真实证据；仅通过设计或演示测试不能发布 |

不重新建立一套产品权威，不用离线HTML替换现有 React/TS/Vite、Tauri/Rust、Python 工程。先核对当前源码，按仓库既有边界完成渐进改造。无已证实的接口时，标“待绑定”并保留未知状态；不创造貌似真实的URL、响应或权限。

## 2. 导航、范围与日常可用性

项目监控为首页，软件与环境、能力资产、用量与缓存、规则与适配为主要入口；诊断与隐私为辅助入口。导入/评价在能力对象内，迁移从选择目标进入，协作摘要在相关项目或能力详情内。保留旧任务、执行、证据的同一对象身份和只读兼容；实验工作流退出默认入口，按原合同返回不支持或归档状态。

项目详情必须根据选中的项目身份打开，DESIGN-LAB 与 AAOS 不重定向到 WORK-LAB。非Git目录、同名目录、worktree及参与软件身份不以名称猜测归属。

日常页面优先呈现当前事实、影响与一个明确下一步；机制解释放入“来源”“详情”“帮助”。高亮仅用于当前选中、需要处理、当前动作，未来未执行步骤采用中性色。未知状态用文字和图标，不把未知等同失败。表格可搜索、过滤、复制身份和展开；观察者不能改变业务项目状态。

## 3. 自适应与可访问性

| 逻辑宽度 | 布局 | 内容与动作 |
|---|---|---|
| ≥1200px | 216px侧栏，主区双列/三卡 | 主操作靠近对象；差异可三列 |
| 768–1199px | 184px侧栏；详情改单列 | 表格保留列标题，局部横向滚动；差异纵向排列 |
| 320–767px | 抽屉导航；卡片、表单、差异单列 | 正文字号保留；操作换行；可选范围与安全门禁不隐藏 |

正文14px，辅助信息13px，正文行高1.6；图标若与文字共同解释不重复朗读。操作区≥44×44px，标签与控件关联，错误贴近字段并提供修正方法。使用语义表格，滚动区可获焦点；不得让整个页面因表格溢出而横向移动。

原型采用真实CSS grid与media query，不用1600px画布transform缩放。设计图中的固定坐标只定义视觉场景。生产实现复用既有响应式组件；字体优先仓库确认字体和系统中文字体，不因预览字体替换全局品牌。

键盘路径：导航→页面主标题→关键字段→主操作；弹窗首项获焦，Escape关闭并返回触发元素；移动抽屉要焦点约束、Escape关闭及焦点恢复。原型提供原生dialog和基础导航，**抽屉焦点约束等仍需生产验收**。Ctrl/Cmd K 在中文composition期间不触发；异步更新不抢焦点、不清空正在编辑的值。生产组件保留展开/滚动位置，不每次刷新重建整页。

## 4. 能力导入与来源评价

导入进入对象资产库，不隐式部署：选择现有已发现来源或本地能力包→取得内容摘要→格式/许可/依赖/请求权限检查→比较现有对象→确认导入→评价入口。

导入预览列出：来源方式、命名空间与身份、版本/摘要、解析格式、许可、依赖、权限、携带配置与新增/更新/冲突项。已有同身份同摘要应复用；同名异身份提示区别；同身份新摘要进入版本差异；冲突不得默认覆盖。无法解析/许可未知/依赖不可得显示具体原因和可执行的修复动作。文件名不是验证证据。

来源评价表：实际样例任务、样例输入引用（遵守隐私范围）、技术观察、结果证据引用、用户判断（有条件推荐/暂不推荐/尚不能判断）、适用条件与限制。版本与来源身份只读来自实际对象；用户评价不自动修改技术结果。评价更新后旧迁移计划需重新核对。真实文件/记录存储由现有服务承担，UI不持有私人原始对话。

本包原型仅演示元数据导入、同名同来源重复提示与用户评价；实际能力包解析预览是图示和生产实施要求。不能对用户宣称原型已经导入可运行能力。

## 5. 目标选择、隔离试用与验证

目标由用户明确选择，无隐式默认发布到某客户端。选择器显示安装身份、形态、实际软件版本、适配器版本、资格、支持字段及限制。不可选项给原因和资格复验入口，不由软件名称推断支持。

迁移详情固定展示源能力/评价版本、目标安装/版本、项目或目录范围、方案版本、功能损失、原生差异、许可依赖与权限条件。许可与损失的确认不能为新的目标沿用。

隔离试用：未开始→提交中→排队/运行→通过/失败/取消/未知。日志区展示当前步骤、已有证据、最后可信进度和来源时间，不仅展示无限转圈。失败说明失败位置、原生修改范围（通常未写入）、重试前提；取消后晚到结果不能复活计划。超时是未知或超时，不自动推导失败或完成。

目标验证必须绑定来源、评价、目标安装/软件版本、适配器、范围、方案与证据版本。在实际目标侧验证加载与目标行为，不能用源端评价代替。源/目标/范围/适配器变更导致旧试用与验证失效；过期资格先复验再允许管理动作。

## 6. 发布与限定恢复

动作区直接显示不可用原因。真实可用性由后端返回：身份、对象、范围、资格、验证、前态摘要/版本、授权引用、过期时间等。确认框仅用于最终限定范围预览，不充当鉴权。

发布流程：前态读回和差异确认→受控提交→写入结果→原生加载读回→目标行为确认。写入成功只更新“写入”；加载成功只更新“加载”；行为通过只更新该范围与该版本的行为结果。后台刷新丢失时保留操作身份并查询同一操作，禁止以新幂等键自动重复写入。

写入后读回失败：显示差异/原因、操作身份、最后可信状态；允许重新读取与限定恢复。行为失败：保留证据，修复后重新验证，或恢复本次范围。权限失效：禁止继续管理命令，仍可读取已获权限范围的结果。

恢复点保存本次触及范围的前态与发布摘要，不保存为“整客户端还原”。仅当前范围仍匹配发布摘要时允许自动恢复；有用户编辑、摘要未知、版本冲突或范围变化时停止，保留现态，进入重新读取/限定合并。恢复写入后同样需要加载与行为复验，不能将“已恢复”自动转为“工作效果正常”。

## 7. 首次接入与规则治理

首次接入：选软件与实际安装→资格与字段能力→最小字段选择→前态/拟写入差异→受控配置写入→原生加载读回→出现真实最小字段活动→范围资格确认。按软件/形态/版本禁用不支持字段并注明原因。缺少基础归属身份不得展示伪完整用量；正文、回复与工具载荷不默认采集。

已经写入但无活动：显示“尚未观察到样例”，不是失败。断连时保留上次可见状态，并将当前软件运行状态显示未知；软件升级后原资格改为待复验。确认前用户仍能返回改选；写入后返回处理读回或恢复，不重复写同一配置。

规则生命周期分别显示意图、原生投影、写入、实际加载、行为验证。三方对照：前态、本方发布态、原生现态。无冲突字段可生成限定合并；冲突字段必须保留现态或由有权限者明确选择。合并预览绑定前态版本，预览后有编辑时提交返回冲突并重新读取，不能覆盖用户新值。

本包原型用单字段演示冲突策略，不能把该简化规则套用于真实结构化配置、列表排序、文本片段或密钥。按现有原生格式与合同处理实际差异。

## 8. 数据、协作与生命周期约束

保留工作、健康、观测三轴；turn_end不是项目完成，断连不是软件停止，无日志不是失败。来源事件时间、收到时间、显示时间与上次正常摘要分别可见。过期数据保留来源与范围，不冒充刷新所得事实。

Token、Credits、订阅、费用与资源指标分开。真实零、缺失、不支持、隐私隐藏、未知/零分母分别展示。估算更新为报告值时替换同一计量身份，不重复叠加；归属未知单列；输入+输出守恒；缓存比例与可判断请求命中率不用同一分母。

WORK-LAB负责项目技术观测与能力适配；AAOS负责知识、人的学习与学习效果；DESIGN-LAB负责专业设计工件与接受。协作在对象内按责任方显示：出域许可、发送、真实接收、知识决定、教学工件、专业接受、教学技术检查、人的学习、反馈、工作效果。没有真实来源时“未取得”，不要创造对端ID或成功回执。长期联合教学不是独立监控或本次UI完成的阻断。

常态最小字段不醒模型、不默认追踪所有任务和子Agent轨迹。诊断限定项目/问题/时间/保留期；元数据也需审查。关闭本方界面、暂停滚动、停止本方观测和外部软件停止分别处理，遵循现有壳合同。

## 9. 执行Agent的结束交付

提供：改动源码和当前提交身份、生成源到投影的追踪、字段/API绑定矩阵、实际验收结果及未通过项、双主题实际浏览器截图、真实客户端接入证据、发布/冲突/恢复结果、旧对象路由回归结果。旧消费者迁移后才归档旧源，保留历史摘要。

设计图和演示测试只能证明设计表达与部分模型逻辑，不证明当前仓库集成完成。生产阻断项未通过时交付可评审分支和明确缺口，不能写“成熟可部署”。本包不扩大任何既有授权，不要求向他人发消息或替其他项目修改权威。
