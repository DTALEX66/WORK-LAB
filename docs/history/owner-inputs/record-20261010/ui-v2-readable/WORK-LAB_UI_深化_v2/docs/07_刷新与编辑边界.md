# 数据刷新、编辑与异步边界

前端读路径与管理命令分开。具体订阅/轮询/取消方式、分页大小及资源上限沿用当前仓库合同；未规定时先量测当前行为并提交可评审方案，不为设计图捏造性能数字。

| 情况 | 要求 |
|---|---|
| 切换项目或目标 | 更新请求上下文；只接纳同一命名空间/对象/范围与当前版本的响应。旧响应不能覆盖新页。 |
| 订阅断连或轮询失败 | 保留最后可信数据和源时间，标记过期/未确认；收到新源事件后才更新事实。 |
| 请求乱序 | 使用现有序列/版本/来源时间合同；收到时间较晚不自动代表事实版本较新。 |
| 用户正在编辑评价/字段/合并方案 | 后台刷新更新只读事实，保留草稿、光标、选项与焦点。前态变更提示草稿需重新预览，不能静默保存。 |
| 用户取消试用 | 取消请求与确认结果分开。过期操作结果可作为历史，不再解锁当前计划。 |
| 用户重复点击或网络重试 | 同操作幂等身份，提交中防重复；结果未知查询原操作。不能仅凭按钮置灰提供幂等。 |
| 管理资格到期 | 立即刷新可用原因；已写入的真实状态保留，不回退显示为未开始。恢复仍需真实权限。 |
| 大表格与长日志 | 使用既有分页/虚拟化与有界缓存；对象ID稳定。暂停滚动只冻结阅读位置，可显示新摘要计数。 |
| 只读恢复与历史补齐 | 仅来源明确支持历史读回时补齐；保留不可补的观测缺口。 |
| 窗口切到后台或关闭 | 沿用原生壳观测生命周期；本方界面状态不等于原生软件状态。 |
| 错误提示 | 对象附近给原因、当前事实和下一步。只有关键新错误主动通知，避免刷新重复刷屏。 |
| 诊断时间范围 | 时间带时区，与源事件时间合同一致；范围、权限、保留期显式确认，不能扩大为全部日志。 |

本包原型使用内存数据与全区渲染，演示操作关系。生产不得照搬该刷新方式；关键表单需要独立草稿状态与按组件更新。Hook保持有界、快速，不唤醒模型，不阻塞原生软件业务。

## 最小数据行为检查

- 页面主项目总量 = 各已归属项目 + 未归属，不因关联项目多次累加。
- 同一请求的estimated→reported更新替换原字段；新revision与真实来源保存。
- 当前计划必须使用实际source/evaluation/target/software/adapter/scope/plan版本匹配的证据。
- 原生发布与恢复每一步保留操作身份、触及范围、前态与结果摘要；客户端不保存密钥作为权限证明。
- 对端接收、人的学习和效果只显示责任方真实来源；当前未接通不生成任何伪事件。
