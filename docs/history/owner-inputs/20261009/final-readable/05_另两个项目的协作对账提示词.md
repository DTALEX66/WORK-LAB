# 另两个项目的协作对账提示词

这是供用户分别交给对应项目的任务输入，不表示 WORK-LAB 已向对端发送或修改其仓库。

## 给 AAOS / ArcheAxis

请把本次长期协作要求与 AAOS 既有蓝图、知识模型、人的知识工作/研究/深度学习、AI 学习资产、人机双向学习和公共接口逐条对账。保留未实现目标，但规划不得写成完成。

三项目是互补体系。AAOS 是共同知识、来源、版本、核验、长期项目记忆与 Human–AI 学习基础；WORK-LAB 在实际编程、AI使用、自动化与治理工作中提供带来源、复现条件、失败/反例、限制的技术候选；DESIGN-LAB 使用获准知识并反馈设计知识，也可把技术/设计知识制作成视觉教学、动画、课件或交互练习。三方可直接/双边/多方合作，各自独立，不建立总控制器。

请确认候选接收与知识可信决定的边界、获准查询的项目/用途/主体/范围、知识和学习目标真实版本、失效/撤回、教学引用及反馈责任。人的原始学习活动与评价留 AAOS；给 WORK-LAB 只返回技术改进所需的最小摘要。所有对端工件ID/回执来自真实责任方，不自己编造集成编号。接收ACK不等于知识认可，技术通过不等于专业设计验收或人学会。

可选最小联合案例是“SUCCESS、exit0、文件存在仍不能证明完成”：WORK-LAB冻结源码复现与三种合成样例可供核验，先由 AAOS 确认知识表达/条件与学习目标，再交 DESIGN-LAB制作内容，WORK-LAB对实际版本检查技术，真人在AAOS判断、解释和完成不同迁移题。反馈按知识/学习组织/设计/技术分流；没有缺陷可真实确认，无效果测量保持未测。此案例不能阻塞三个项目独立基础功能。

仅在 AAOS 自身授权范围对现行权威、机器索引、前端职责、规划、生成源和测试对账；沿用现有结构，不重建第二知识系统。报告真实现状、待实现增量和不一致处，保留旧证据与替代关系，不把WORK-LAB历史审计当作AAOS已接入证明。

## 给 DESIGN-LAB

请把本次长期协作要求与 DESIGN-LAB 既有定位、设计专用执行内核、全品类作品、专业知识与公共接口逐条对账。它是设计生产与专业表达系统，可有自己的内核，也可使用外部AI软件；不能被缩成WORK-LAB插件或仅做课件的工具。专业设计状态、原生作品与专业验收归本项目。

三项目互补：从AAOS读取获准知识/规范/来源与版本，用设计实践反馈新候选；把适合人的知识或WORK-LAB技术案例转化为视觉讲解、动画、课件、交互练习；教学进入AAOS人的学习，再按责任反馈完善知识、设计表达和实际技术工作。直接、双边、多方按需，独立运行发布，不每次强制经第三方。

对教学产物绑定真实工件ID、内容修订/摘要、知识和学习目标版本、源素材/许可、示例版本及专业验收。WORK-LAB只检查具体教学版的数字、命令、代码与技术事实，不代替专业验收；AAOS负责学习活动和评价，Agent不能代填真人学习。收到技术检查不代表人已经理解。

可选先做“正常退出、文件存在、内容符合、验收接受”的最小案例：一份可编辑视觉讲解加一个先判断后看结果的交互练习即可，不要求同时动画、视频和完整课程。原源码故障与合成教学输入必须区分，不能演成用户历史事故；实际内容改版后相关技术事实重新检查。

图示/节奏/交互易误解归DESIGN-LAB；知识依据/条件、学习组织归AAOS；示例不能复现和代码行为归WORK-LAB；不明共同分诊。反馈与修订真实读回，不伪造提升。沿自身授权整理现行定义、接口、前端协作入口、生成源和旧资料，不改其他仓库，不宣布三方已集成；未实现的长期目标继续保留。
