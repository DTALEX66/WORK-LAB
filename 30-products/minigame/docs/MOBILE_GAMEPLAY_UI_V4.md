# 抖音竖屏小游戏 UI / 玩法 V4

## 目标

把当前“桌面后台缩小版”重构为 3 秒吸引、15 秒学会、单手可玩的 CCTV 放行游戏。

核心规则只有一句：

> 三项信息对得上就放行，对不上就封锁。

## 官方与真机约束

- 设计宽度：750；按 393px 手机换算比例约 0.524。
- 顶部使用运行时安全区，倒计时避开右上角系统胶囊。
- 主要玩法文字：设计字号 28–36（约 14.7–18.9 CSS px）。
- 辅助文字：不得低于设计字号 22（约 11.5 CSS px），不放关键规则。
- 主按钮高度：164 设计 px（约 86 CSS px），明显超过 48 CSS px 触控基线。
- 非必要英文全部移除；不能用颜色作为唯一信号。

## 动态布局（750设计宽）

```text
safeTop + 12     顶栏 76
safeTop + 96     一句话规则条 66
safeTop + 170    CCTV，动态高度 clamp(H-safeTop-644, 520, 880)
CCTV + 12        三项读数 108（楼层 / 人数 / 门）
读数 + 12        巡检双主按钮 220（放行 / 封锁；间歇期显示不可操作状态）
按钮 + 12        单行反馈区，填满底部安全区
```

### 视区占比

- 393×852：CCTV 有效场景约 42–47%。
- 360×640：CCTV 有效场景不低于 35%。
- 删除七格状态面板、两条常驻资源条、五行日志、四键主操作台。

## 视觉方向

延续已经落地的厚重、磨损机械监控台结构，而不是只取黑绿色：

- 主体是一块厚重、磨损的机械监控台；
- CCTV 是最大单一表面；
- 按钮是实体金属键，有边框、螺钉、指示灯、压下反馈；
- 红色只用于封锁/失败，绿色只用于放行/通过；
- 禁止大面积圆角 SaaS 卡片、细碎小框、英文伪代码、无意义微字；
- 内嵌 HUD 只保留三项大读数和一条中文状态；
- 旧状态图的固定英文、固定 07 和答案文字必须继续遮盖。

## 首局教学

1. **第一班（正常）**：规则条写“信息一致，点放行”，放行键呼吸；第一次误点不扣分，保持本题。
2. **第二班（异常）**：规则条写“发现矛盾，点封锁”，封锁键呼吸；第一次误点不扣分。
3. **第三班起**：只显示“对得上就放行，对不上就封锁”，取消答案高亮。

正常与异常巡检标题统一为“核对画面与数据”，不得通过标题、边框、`SIGNAL VARIANCE` 或推荐键泄题。

## 60秒循环

- 第一异常：8秒。
- 后续异常间隔：8–11秒；目标 6–7 个异常/局。
- 异常间插入一次 4 秒正常巡检；目标 5–6 个正常班次/局。
- 正常放行后电梯自动关门/上行，玩家不需要手动驾驶。
- 异常封锁后系统自动执行现有映射的门锁、重启或记录核验，并播放 0.8–1 秒动作反馈。
- 基础 60 秒模式不再出现第二层处置按钮；复杂处置只留给后续高级模式。
- 无论判断正确或错误，本轮异常都会在反馈后被隔离，避免残留污染下一轮。

## 计分

- 判断正确：100 + 剩余秒数×10。
- 判断错误：连击归零，稳定度 -12。
- 自动处置不额外计分，避免玩家因系统动作获得不可理解的奖励。
- 顶栏只显示：剩余时间、分数、连击。

## 声光反馈

- 正常：到站铃、绿色许可灯、门关闭/上行。
- 异常：100–150ms 声音抽空、一次低频冲击、短故障条、红色封锁灯。
- 判断正确：实体按键压下 + 清晰确认音。
- 判断错误：画面冻结短暂指出冲突，不使用长篇日志。
- 强闪不超过每秒 3 次；静音时仍能从图标、文字、形状判断。

## 验收

- 393×852 和 360×640 无关键内容被胶囊/手势条遮挡。
- 关键文字真机换算 ≥14 CSS px；反馈文字 ≥12 CSS px。
- 两主按钮 ≥48 CSS px 高。
- 首屏不看说明即可看到规则与两个动作。
- 前两轮教学可完成；第三轮无提示可独立判断。
- 判断前无标题、日志、颜色框或推荐键直接泄露答案。
- 正常放行会产生门/楼层的可见变化；异常封锁会产生可见锁止反馈。
