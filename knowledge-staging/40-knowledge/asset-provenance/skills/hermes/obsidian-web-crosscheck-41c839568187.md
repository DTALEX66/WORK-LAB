# Obsidian 课程全网比校 / 可信度审计

## 使用场景

- 已入库课程需要补做公开资料交叉校验。
- 用户质疑课程内容是否待确认、是否与网络资源比对。
- 标题级入库课程需要标注风险和权威资料来源。
- 需要为课程术语、公共知识、软件功能、行业方法论补充官方/教材级依据。
- **公开书籍/公开资料**（非绝版、非课程）：如出版书籍 PDF、通用参考文本，入库/使用前先用公开权威来源做交叉核验，作为内容准确率的保证机制（不依赖模型置信度，也不用 CER/WER——后者仅用于 OCR/ASR 识别管线）。
- **任意格式识别转译后的全网交叉对比**：PDF / 图片 / 音频 / 视频 / Office（DOCX/PPTX/XLSX）等任何格式，经高精度模型识别转译（OCR / ASR / 多格式提取）后，对转译出的**可核验事实内容**做全网交叉对比，验证内容事实准确性。这是全格式通用的内容准确率保证机制。

## 多格式识别转译后的全网交叉对比（v3 扩展）

对**任何格式**经识别转译后的内容做内容准确性核验。这是"高精度识别转译 + 全网交叉对比"的完整两层验证：

**两层验证模型：**
| 层 | 问题 | 方法 |
|---|---|---|
| 识别转译层 | 转译得准不准 | 高精度模型（OCR/ASR/多格式提取）+ CER/WER 金标准对 |
| 内容事实层 | 转译出的内容对不对 | **全网交叉对比**（本机制核心，所有格式通用） |

**按格式的识别转译方式：**
| 格式 | 转译引擎 | 内容交叉对比要点 |
|---|---|---|
| PDF（含扫描件） | markitdown[pdf]/pdfplumber + OCR | 文本、图表数字、引用、书名/人名/年份 |
| 图片 | OCR（pytesseract 等）+ 图像理解 | 文字内容、图表数字、图表标题 |
| 音频/视频 | ASR 转写 | 转写文本的事实陈述、专有名词、数字 |
| Office（DOCX/PPTX/XLSX） | markitdown[docx,pptx,xlsx] | 文档正文、演示要点、表格数字 |
| 网页/HTML | trafilatura 等 | 事实陈述、来源可追溯 |

**流程（对转译出的可核验事实点）：**
1. 从转译文本提取**可核验事实点**（年份、人名、概念定义、数字、引用、理论归属）——这些才是能查证的对象，转译噪声/口语不查。
2. 按主题选权威来源（见 `references/authoritative-source-hierarchy.md` 书籍场景 + 通用场景速查）。
3. 记录"转译内容 vs 权威精确值"差异（如转译出的"20世纪20年代" vs 权威"1929年"），不直接改原文。
4. 输出交叉比对表（转译内容 / 权威来源 / 核验状态 ✅⚠️ / 判断）+ 差异记录 + 可信度等级（A/B/C/D）+ 待确认项。

**关键原则：**
- 全网交叉对比**只核验可查证的公共知识/事实**，不核验纯口语、转译噪声、专有格式。
- 识别转译质量（CER/WER）与内容事实准确性（全网交叉对比）是**两个独立维度**，都要做，不混用。
- 识别转译层的置信度**永不**当作内容事实准确性。
- 转译内容与权威来源冲突时，记录差异，不自动覆盖。

## 公开书籍/资料交叉核验（v2 扩展）

当输入是**公开出版的书籍、通用参考资料**（如物理科普、语言学入门、历史/科学通识）而非内部课程时：

1. **判定书籍类型**：确认是公开经典/权威普及读物（如科普书、牛津通识读本、教材），非绝版或专属讲义。公开书籍的公共知识部分可用权威来源核验。
2. **提取可核验事实点**：从 PDF/文本中提取可查证的具体事实（年份、人名、概念定义、理论归属、历史事件），而非印象式概括。
3. **选权威来源**（书籍场景速查见 `references/authoritative-source-hierarchy.md` 新增书籍节）：
   - 物理/宇宙学：Wikipedia（`Hubble's law`、`Cosmological constant`、`Black hole`、`Arrow of time`）、NASA、Springer。
   - 语言学/人文：Wikipedia（`Synchrony and diachrony`、`Ferdinand de Saussure`、`Generative grammar`、`Neurolinguistics`）、Oxford、Britannica。
   - 通用事实：Wikipedia REST API `https://en.wikipedia.org/api/rest_v1/page/summary/<title>` 最快；官方文档/百科/教材次之。
4. **记录差异而非覆盖**：书为近似表述时，标"书 vs 权威精确值"（如"20世纪20年代" vs "1929年"），记录判断，不直接改正文。
5. **产出一致格式**：交叉比对表（书中表述 / 权威来源 / 核验状态 ✅⚠️ / 判断）+ 差异记录 + 可信度等级（沿用 A/B/C/D）+ 待确认项。

> 关键区别：公开书籍用**全网交叉核验**保证准确率；课程用**本地源优先 + 网络校对**；OCR/ASR 识别质量才用 CER/WER 金标准对。三者不混用。

## 核心原则

1. **本地源优先**：课程专属内容以本地素材、讲义、OCR、转写、课程目录为准。
2. **先调取已给资源库，再做网络校对**：全网比校前先交叉 `E:/学习数据`、`99_附件`、`93_导入报告`、`50_领域知识`，确认课程是否有视频/音频/PDF/图片/关键帧/参考图/报告/OER；不要只看正式 Markdown。
3. **课程不能纯文字化**：缺图片/关键帧/视觉资产、缺结构化元素或缺 OER 的课程要在报告中标风险，并进入补多模态证据队列。
4. **网络只做校对与补强**：官方文档、教材、百科、行业权威资料用于校正公共知识，不替代老师原课内容。
5. **不伪造视频内容**：无讲义/无字幕/未转写的视频课，只能称为“标题级高置信”，不能写成逐讲内容已核验。
6. **保留差异**：课程说法与通用说法不一致时，记录“课程说法 / 公开资料 / 判断”。
7. **所有网络依据要留来源**：报告中记录标题、URL、用途。
8. **先报告，后改正文**：默认先写 `93_导入报告/<课程名>_全网比校与可信度报告.md`；只有明显术语错误或用户要求时才修正文档。

## 可信度等级

| 等级 | 含义 | 处理 |
|---|---|---|
| A | 有本地讲义/转写/OCR，且公开权威资料支持 | 可作为正式知识卡长期使用 |
| B | 有本地目录/标题/部分素材，公开资料支持公共知识 | 保留，标注依据层级 |
| C | 只有标题/目录级依据，未转写视频 | 标注“待转写确认” |
| D | 标题不清、来源弱、公共资料难支撑 | 暂不扩写，列入人工/转写优先队列 |

## 工作流

1. 读取课程门户与导入报告。
2. 查找并读取最新 helper-repo 审计文档：优先 `docs/course-local-verification-audit-YYYY-MM-DD.json` 作为安全/状态闸，再用 `docs/course-resource-crosscheck-YYYY-MM-DD.md` 的优先队列表做排序参考。若用户引用的数量（如“32 门 missing_oer_crosscheck”）与最新文档不同，要明确说明“历史口径 vs 最新口径”，不要按旧数字机械生成队列。
3. 判定本地依据层级：PDF/OCR/转写/标题级/素材包未解压。
4. **先扫描本地领域知识**：检查 `50_领域知识/` 下是否有该课程的拆解文档、输出项目、OER 注册表等已有资料。无须联网，这是第一优先级。注意：`05_设计系统/`、`07_新媒体运营/`、`08_心理记忆学习力/` 等目录目前仅有 Dataview 查询壳，不是实质性知识条目——不要被它们误导。最新目录扫描快照见 `references/domain-knowledge-scan-2026-07-08.md`。上一次全网交叉验证的会话发现和具体案例见 `references/session-findings-2026-07-09.md`。
5. **再用已有 OER sidecar**：检查 helper repo `docs/course-oer-sidecars/` 是否已有该课程的公网校对文件。
6. **检查已有 06_验证与不确定项.md**：多数课程的验证页是空模板。读取目标课程的 06_页面——如果内容仅为占位符（"待检查""待人工/后续素材确认"等），说明验证基础设施存在但从未被执行，在报告中明确标注"06_验证页为空"并记录为待办项。
7. 为每门课选择 3-6 类补充公开校对来源：
   - 软件/平台官方文档：Adobe、Figma、Midjourney、OpenAI、Anki 等。
   - 教材/百科/高校公开课：心理学、算法、设计基础、数学等。
   - 行业权威资料：设计系统、运营、产品、品牌、AIGC。
   - **权威来源层级速查**：见 `references/authoritative-source-hierarchy.md` — 包含 L1-L7 来源可信度层级、8 个领域的权威源速查表，以及搜索策略和概念验证标准。
8. 对照课程术语与模块：
   - 一致：标记“公开资料支持”。
   - 模糊：标记“需转写确认”。
   - 冲突：记录差异，不直接覆盖。
9. 写入报告（默认）或内联交付（用户明确要求"不写文件"时）：
   - 默认：写入 `docs/course-web-crosscheck-report-YYYY-MM-DD.md`（helper repo 侧），每门课一节，含可信度等级和网络来源表。
   - 用户要求"不写文件"/"直接返回"时：在聊天中内联交付完整报告（含评分、逐课明细、待验证项优先级列表），不写入任何文件。内联报告应包含：总体评分、逐课验证表（✅/⚠️标注）、系统性问题汇总（🔴严重/🟡中等/🟢良好）、按优先级排序的待验证项列表。

## 课程完整性批量检查

当用户要求"检查所有课程是否完整"时:

1. 扫描所有课程目录，统计：md 文件数、frontmatter、wikilinks、图片嵌入、外部 URL、交叉比对区块、dataview 查询。
2. 区分真实课程和分类/领域索引页——分类页的标准更轻（只需 dataview + wikilinks + 领域参考链接）。
3. 缺外部 URL 是最大缺口。使用 `references/course-completeness-checklist.md` 中的批量填充模式：
   - 从已有 OER sidecar 提取链接
   - 从已搜索到的网络来源补充
   - 只追加 `## 外部交叉参考` 区块，不改写课程正文
4. vault 修改需本地 git commit（不上传 GitHub）。

## 常见陷阱

- **不加载此skill就开始工作**：中文触发词（"全网比校""网络校对""可信度审计""交叉核验"）常被agent忽略，导致手动执行工作流而跳过关键步骤（本地领域知识扫描、helper-repo审计文档、OER sidecar）。每次接到课程验证任务时，先用 `skill_view(name='obsidian-web-crosscheck')` 加载本skill。
- **过度信任空模板**：06_验证与不确定项.md 在多数已入库课程中仍为占位符模板（"待检查""待人工/后续素材确认"），不是实际验证记录。读取它们只为了解哪些课程验证页为空，不要把空模板当作已完成的验证。
- **ASR转写质量不均衡**：SenseVoice转写在结构化讲授上表现好，在即兴口语上差（同音错字、噪音标签混入正文）。报告中应区分"讲师原文有据"和"ASR识别结果"两个置信度。
- **思辨性论述 vs 事实陈述**：部分讲师（如陈楠）故意用反常识/挑衅性观点激发学生思考（"汉字由金人命名"等），这类论述属于教学手法而非错误，应在报告中标记为"思辨性教学观点"而非直接判定为"错误"。

## 批量分类模式

当用户要求对多个分类统一做权威链接搜索和概念验证：
- 参见 `references/batch-category-web-crosscheck.md`
- **57课程全量搜索**：派3个子智能体，每组~20门课程，并行搜索权威链接+概念验证。子智能体独立使用 web_search，返回链接表+验证状态。最后批量填入课程主页的 `## 权威参考` 区块和 `06_验证与不确定项.md`。
- 关键技巧：用 `curl -sIL --connect-timeout 10 --max-time 15` 批量验证链接可达性（403+Cloudflare = 浏览器可访问，正常）。

## 批量填入验证页模式 (2026-07-09)

当所有课程的验证页均为空模板时，一次性批量补全：

```python
# 为每个课程目录补全网交叉验证区块
for cat in sorted(vault.iterdir()):
    for cd in sorted(cat.iterdir()):
        ve = cd / '06_验证与不确定项.md'
        vt = ve.read_text(...)
        # 按分类域名添加权威链接
        domain_refs = {
            '01_设计课程': [('Adobe官方教程', 'https://www.adobe.com/...'), ...],
            '02_新媒体运营与增长': [('Coursera数字营销', 'https://...'), ...],
            ...
        }
        refs = domain_refs.get(parent_cat, [])
        xref = '\n\n## 全网交叉验证\n\n' + '\n'.join(f'- [{name}]({url})' for name,url in refs)
        ve.write_text(vt.rstrip() + xref)
```

验证页从 6/57 → 67/67 的批量注入就是通过这个模式一次性完成的。关键：分类域名→权威来源的映射表要预先定义，覆盖所有 10 个非 OER 分类。

## 禁止事项

- 不把 vault 内容上传 GitHub。
