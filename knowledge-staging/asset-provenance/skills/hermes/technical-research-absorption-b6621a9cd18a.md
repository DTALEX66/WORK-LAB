# Technical research & absorption

## Trigger

User asks to search the web / GitHub / HuggingFace for enhancements ("还能增强工作流的吗 / 去全网找找 / 这里也找找") and to absorb the findings into the project ("吸收到项目里"). The deliverable is a **tracked archive + skill absorption + cloud upload**, not a chat summary.

## Search-source strategy (2026-08-12 validated)

- **GitHub API first** — real, usable tools with stars; far more reliable than search engines:
  - `gh search repos "<query>" --sort stars --limit 8 --json fullName,stargazersCount,description`
  - Direct repo check: `curl -s https://api.github.com/repos/<owner>/<repo>` (public API, no auth needed)
  - Note: `gh api search/repositories` can 404 on argument shape; `gh search repos` is the reliable form.
- **Search engines are noisy**: DuckDuckGo html endpoint rate-limits quickly (returns empty on later queries in a batch); Bing redirects to a zh-CN result set and returns dictionary/encyclopedia junk for English queries. Use them sparingly, batch spaced out, and expect garbage; do not conclude "nothing exists" from an empty engine result.
- **HuggingFace needs the system proxy** (Clash 127.0.0.1:7890): direct connects time out (HTTP 000). `curl -x http://127.0.0.1:7890 https://huggingface.co/api/models?search=...&sort=downloads&direction=-1`. HF holds models/courses/leaderboards (framework code lives on GitHub), so weigh its findings accordingly.
- **Fetch articles with** `curl -s -L -m 40` + a UA, then strip scripts/styles/tags via Python regex. Some blog pages 404 or return JS shells — skip and rely on GitHub primary sources instead.
- **GitHub API from execute_code intermittently SSL-fails** (`ssl.SSLEOFError: UNEXPECTED_EOF_WHILE_READING`) on direct connects. Validated retry pattern: loop `for proxy in [None, 'http://127.0.0.1:7890']`, build a `ProxyHandler` opener per attempt, retry ×3 with sleep 2. This makes repo-metadata, contents-listing, search, and PR/merge calls reliable. Same pattern for codeload tarball downloads.
- **Search API rate-limits hard without auth (validated 2026-08-14)**: a multi-query search batch over `api.github.com/search/repositories` dies mid-way with `HTTP Error 403: rate limit exceeded` when unauthenticated (~10 req/min unauth). Fix: pull the token once via `git credential fill` (protocol=https / host=github.com) and add `Authorization: token <40-char>` to the search request — authenticated search quota is ~30 req/min and the same token later powers PR/merge calls anyway. This let a 13-batch absorption run keep discovering new candidates instead of stalling on the quota.

## Filtering (user constraints)

- **Exclude gate/verification classes** unless asked: CI gates, exact-SHA checks, quality gates, evaluation benchmarks. The user already has a final-line quality gate and explicitly wants everything EXCEPT that.
- Keep: orchestration, coordination, session lifecycle, observability/tracing (not gates), memory/context, task management, spec-driven planning, engineering controls, safety boundaries.
- Distinguish "official known bug" from "config drift": when a tool resets state (e.g. Codex Desktop re-login/appearance reset), check the vendor docs + GitHub issues BEFORE blaming local config. Community issues with the same version line are decisive evidence (e.g. openai/codex #37927).

## Absorption workflow (WORK-LAB pattern)

1. **Tracked archive doc** in `50-taskpacks/<TOPIC>-<YYYYMMDD>.md`: research sources (repo/star/URL table), distilled directions with **landing paths + acceptance criteria** per item, status checkboxes. Cloud-visible; `.hermes/` is NOT for this.
2. **Absorb into a managed skill** lightly: patch the most relevant `codex-assets/skills/*` (e.g. single-writer-delivery got a DAG-orchestration extension) — keep under the ~10KB skill budget; no new heavy skills for one-off content.
3. **Overlay sync**: `python scripts/workflow/sync_codex_global_assets.py apply && verify` — expect occasional `BLOCKED` (Codex Desktop rewrites config.toml and dissolves the managed block, a known recurring behavior): back up `.workflow-assistance-state.json`, downgrade `version` 3→2, re-apply (legacy-migration path), verify PASS.
4. **Regenerate CURRENT_STATE** after any tracked change (stale digest fails
   every downstream PR CI). WORK-LAB now automates this: `.githooks/pre-commit`
   detects tracked changes and regenerates + stages CURRENT_STATE on commit
   (enable on a fresh clone with `git config core.hooksPath .githooks`).
   With the hook active you do NOT need the manual step; without it, run
   `python scripts/ci/generate_current_state.py --root .` before committing.
5. **PR + CI + merge**: branch `docs/…` or `feat/…`, commit, push, `gh pr create`, wait for 5/5×2 green, squash-merge, `git fetch && git merge --ff-only origin/main`, verify local==remote SHA and clean worktree.
6. If the target repo is a **different project with a concurrent session** (dirty worktree, non-main branch): do NOT commit — archive the diff as a patch under `<owner>/.hermes/task-artifacts/external-recovery-*/` and report; the parallel session may already have pushed it (verify `git branch -r --contains <sha>`).

## Design-SKILL absorption (DESIGN-LAB pattern, 2026-08-13 validated)

For absorbing **design SKILLs / design-system content** (open-source design skills for AI coding assistants) into a design-lab style project. Different from the WORK-LAB pattern — it vendors whole skill trees, not overlay configs.

1. **Discover via GitHub search**: `https://api.github.com/search/repositories?q=<query>&sort=stars` — queries like `"design skills"`, `"claude code design skill"`, `"design skill agent"`. Top hits (2026-08): `nextlevelbuilder/ui-ux-pro-max-skill` (116k★, MIT), `Leonxlnx/taste-skill` (76k★, MIT), `Nutlope/hallmark` (24k★, MIT), `alchaincyf/huashu-design` (22k★, MIT), `ConardLi/garden-skills` (10k★, MIT).
2. **License gate first**: verify MIT via repo API `license.spdx_id`. MIT = redistributable + model-input + commercial OK. NO-LICENSE / NOASSERTION → quarantine, never vendor. **Nuance (2026-08-14): repo metadata says MIT but the tarball contains NO LICENSE file → do NOT vendor; register `integration_mode: reference` + `status: reference-now`** (keeps it tracked as a candidate; a future session can vendor once the author adds a license). Real case: `content-designer/ux-writing-skill` (147★) had no LICENSE in-tree — registered reference-only instead of vendored.
3. **Fetch via codeload tarball, not git clone**: `https://codeload.github.com/<owner>/<repo>/tar.gz/refs/heads/<branch>` (check `default_branch` — huashu-design uses `master`!). Use urllib from execute_code with proxy fallback (`http://127.0.0.1:7890`), retry loop — the terminal wrapper misparses `https://` as a drive path and blocks clone. Extract with `tarfile.extractall(filter='data')` into `.hermes/task-runtime/`.
4. **Vendor the skill tree**: copy `SKILL.md` + `references/` (skip large `assets/`, `cli/`, `demos/`, `node_modules` — user rule: never copy large binaries). Land per capability: `knowledge/visual-quality/` for anti-slop/frontend skills, `knowledge/production/` for animation/video pipelines, `intelligence/` for data-heavy design-intelligence CSVs.
5. **Every vendored tree carries**: upstream `LICENSE` copy + a `SOURCE.md` (origin URL, author, license, date, mode, usage, redistributable/model-input/commercial booleans). **Pitfall: the upstream license file may be named `LICENSE.txt` (ui-clone-skills did), so locate it with `rglob('LICENSE*')`, not a hardcoded `LICENSE` path** — a hardcoded lookup silently no-ops (reported "LICENSE 缺失" but a `LICENSE.txt` existed), leaving the vendored dir unlicensed and tripping the license gate later.
6. **Register in SOURCE_REGISTRY.json**: entry schema enums are strict — `integration_mode` ∈ {vendor-adapt, adapter, derive, reference, quarantine}; `status` ∈ {adopt-now, adapter-next, reference-now, review-required}; `source_tier` ∈ {A,B,C,D}; `license_verified` bool. **The origin link field is `url` (must start `https://`), NOT `source`** — the verifier (`verify_source_registry_v2.py`) fails every entry using `source` with "canonical https URL required". **Every entry ALSO needs a unique `id` field** (validated batches 11–12): the verifier treats `id` as the uniqueness key (`if e.get('id') in ids: duplicate id`), so a new entry without `id` collides as `entry[158] None: duplicate id`. Derive it from the directory name (`qiaomu-design`, not the full path). A missing `id` on ONE batch slips past CI (the verifier only re-validates the whole registry on the next run), so when you add a batch, scan the whole registry for `"id": null` entries and backfill in the same commit. Unassessed candidates go `quarantine`/`review-required`. Validate with jsonschema after appending; a wrong enum fails the whole registry.
7. **Check identity gate after vendoring**: absorbed content rarely trips a legacy-name identity gate (it scans active product paths), but your own ROADMAP/migration docs can — write legacy-name mentions with the gate's exempt phrasing (`已退出活动命名` / `历史归档`).
8. **Post-absorption governance audit (2026-08-14 validated)**: after N sources are absorbed, verify ALL of them in one pass before PR — not just the latest:
   - every registry entry has `license_verified: true`, `license` ∈ {MIT, CC0-1.0}, `integration_mode: vendor-adapt`, `status: adopt-now`;
   - every vendored directory contains `SOURCE.md` + `LICENSE` (or `LICENSE.txt`) with a non-trivial file count;
   - the registry's strict schema enums still validate (a wrong enum fails the whole registry — 124 entries, one bad enum → total fail).
   This catches half-vendored batches (e.g. a directory copied but never licensed) before they reach CI.
9. **Vendored trees with source code trip the License-hygiene CI gate**: if an absorbed tree contains `.py/.js/.mjs` files (game-ui-mobile 28, ppt-agent 18, anydesign 7, motion-engine 6), `verify_license_coverage.py` (CI license-secret-gate) fails on missing SPDX headers even when all other checks pass locally — the aggregate `verify_design_lab.py` does NOT include it. Fix: add every vendored dir to that script's `EXCLUDE_PREFIX` (REUSE semantics: vendored trees carry their own LICENSE). **Pitfall: prefix paths are relative to `design-lab/`** (the script runs `git ls-files` with `cwd=REPO` where REPO = script's parents[1]), so use `knowledge/visual-quality/game-ui-mobile/` — NOT `design-lab/knowledge/...` — or the exclusion silently never matches.
   - **Binary assets need the exclusion too — and historically the check lacked it**: if a vendored tree ships `.png/.jpg` (claude-design-skill `docs/images/`, ecommerce-ai `social-preview.png`, springy-motion `assets/`), the *binary-sidecar* half of the check (`check_binary_sidecars()`) originally did NOT call `is_excluded()` → CI "License & secret hygiene gate" fails with `MISSING sidecar: <vendored>.png` even after the source-header exclusion works. Fix was one line: `if not rel.lower().endswith(BINARY_EXT) or is_excluded(rel): continue`. When you patch this script, verify BOTH loops respect exclusion.
   - **Per-batch completeness**: every new vendored dir must be added to `EXCLUDE_PREFIX` in the SAME commit as the vendoring. Easy to miss half the list (batch7 added the two `intelligence/` dirs but forgot `knowledge/visual-quality/springy-motion/` and `design-thinking/` → CI failed again). Before pushing, grep the exclusion list for every new dir under BOTH `knowledge/` and `intelligence/` subtrees, then run `verify_license_coverage.py` locally (aggregate verifier won't catch it).
   - **Diagnostic shortcut**: when BOTH "License & secret hygiene gate" AND "Python gate" show red on a vendoring PR, fix the license coverage first — the Python gate failure is usually downstream of the same missing-exclusion (or an anti-slop scan-scope issue), and both flip green after the license fix. Don't burn turns debugging the Python gate independently.
10. **Anti-slop / repo-wide scans need skip-scope or vendored content floods them**: `check_anti_slop.py design-lab/` scans every `.html/.css` under the tree; vendored templates (baseline.html, style-tile.html), benchmark fixture implementations, and historical protocol assets (design-system/) produce hundreds of false AI-default findings. Fix: pass `--skip-prefixes knowledge/,intelligence/,templates/,evals/,exports/,domain-packs/uiux-design/benchmarks/,design-systems/` (prefixes must match the real rel-path segments — `domain-packs/uiux-design/benchmarks/`, not a truncated `domain-packs/benchmarks/`). **Pitfall: a `.` target inside a subprocess-run verifier resolves to the parent's cwd (repo root), not the script dir — pass an absolute path or resolve explicitly**, or you'll scan `.hermes/task-runtime/` extraction leftovers (terrazzo/hallmark dumps, hundreds of files).
11. **Prohibition statements self-trigger their own gates**: a policy doc line like `禁止绑定 0.0.0.0` matches the gate's own `0.0.0.0` forbidden-pattern check → FAIL. Fix: gate exempts lines containing negation words (禁止/不得/不自动/not) before scanning forbidden patterns — same exemption pattern as the identity-gate legacy-name allowlist.
    - **Repo-wide gates ALSO trip on their own unit-test files (validated PR #53).** When you add tests for a gate's detection logic, the tests legitimately embed the forbidden vocabulary as fixtures (`test_core_gates.py` contained `OPEN-DESIGN-Assistance` strings to assert detection) — and the gate scans the WHOLE repo (`ROOT.rglob("*")`), so it FAILS on your own test file (`IDENTITY_GATE=FAIL design-lab/tests/test_core_gates.py: OPEN[- ]DESIGN[- ]Assistance`). Fix the GATE, not the tests: exempt the tests dir (`if rel.startswith("design-lab/tests/") and rel.endswith(".py"): continue`) with a comment explaining fixtures are semantic requirements, not violations. General rule: any gate that scans the full tree needs a test-dir exemption the moment you write tests for it. Also verify the aggregate after adding gate tests — the local `pytest` pass does NOT mean the repo-wide gate passes.
12. **Generated JSON must be deterministic**: a `generated_at` with seconds means every regeneration diffs the file → CI clean-tree gate + noisy PRs. Fix: date-only timestamp (`%Y-%m-%d`) + sort entries by path.
13. **Verification**: full test suite + registry schema validation + identity gate, then branch → PR → CI green → squash-merge → sync main. Before pushing a batch that adds vendored source code, run `verify_license_coverage.py` locally — the aggregate verifier won't catch it and CI will.
14. **Clean extraction leftovers after every merged batch**: delete `.hermes/task-runtime/batchN-extract/` and `bN-*.tgz` once the batch is merged (accumulated ~166MB across batches 2–6). Leftovers also flood scans if a verifier's cwd resolves to the repo root (see anti-slop pitfall in 10). Make cleanup part of the batch loop, not an afterthought.
    - **Dedup candidates against what's already absorbed BEFORE downloading (validated batch 13).** By the 13th batch the same top-star repos recur across every search query (`nextlevelbuilder/ui-ux-pro-max-skill`, `Leonxlnx/taste-skill`, `Nutlope/hallmark`, `alchaincyf/huashu-design`, `JimLiu/baoyu-design`, `AThevon/genjutsu`, `dominikmartn/hue` all reappeared). Keep a running set of absorbed repo names (the SOURCE_REGISTRY `url` field is the key) and filter search results against it in the same execute_code pass — don't waste a download+extract cycle on something already vendored. **Saturation signal: when a fresh query's top hits are >60% already-absorbed names, the surface is effectively mined** — stop adding new batches and pivot to hardening (test coverage for verifiers, generated-index finalize, governance sweeps) rather than forcing marginal picks. Also prefer the authenticated search token (step 1) so the batch's later queries don't hit the unauthenticated rate limit mid-sweep.
15. **Never nest aggregate verifiers inside each other**: a `verify_*` script that subprocess-invokes the aggregate `verify_design_lab.py` (e.g. a release-gate checking "verify chain green") recurses forever — release gate → aggregate → release gate → … → the whole run times out (120s). Fix: aggregate verifiers communicate status via a marker file (e.g. the aggregate writes `config/.verify-chain-ok`; consumers check `marker.exists()`), or call leaf verifiers directly. Also keep release-only gates OUT of the daily aggregate chain (they need a clean worktree + human approval, so running them inside the aggregate produces false BLOCKED/dirty findings); run them standalone with a `--skip-dirty` escape hatch for the aggregate context.
16. **Finalize PR after N batches — regenerate generated indexes + update records in ONE dedicated batch** (not inside a content batch): after absorbing many sources, run the repo's generated-index generator (e.g. `generate_capability_indexes.py`) so ALL absorbed assets are indexed (this session: 515 → 1938 after 10 batches, then **1938 → 2222 after batches 11–13, PR #62 — finalize is RECURRING, not one-time**: every further batch group leaves the index + absorption-record stale again, so budget a repeat finalize after each batch group, not just once at the end), update the absorption-record doc to the full batch state, and sync the ROADMAP's absorption counts. **Detect staleness concretely, don't guess**: grep the generated index JSON for a couple of the newly-absorbed dir names (`"hue" in text`, `"qiaomu" in text`) — absent names mean the index predates the batch (this session: index still said `count=1938` with `generated 2026-08-13` while batches 11–13's five dirs were all absent; one `generate_capability_indexes.py` run took it 1938 → 2222). The `generated_at` timestamp is the cheap tell: compare it against the last absorption commit date before trusting a count. Ship that as its own `docs/finalize` PR so the index diff doesn't pollute content PRs and the record reflects reality at the end, not mid-stream. Also do a **post-N-batch governance sweep** before finalize: check every registry entry has `url` (not `source`) + `license_verified` + valid enums, and every vendored dir has SOURCE.md + LICENSE — catches half-vendored batches that slipped past per-batch checks.
    - **Automate the boundTree freshness check in CI so the rebind is not a manual ritual (validated PRs #44–#48).** Add a `--check` mode to the rebind tool (`update_evidence_binding.py --check` = verify-only; no args = rebind) and a CI step that runs it. Two design traps: (a) **PR chicken-and-egg** — on a feature branch `HEAD` ≠ the main-bound tree, so a strict `== HEAD` check fails EVERY PR; the step must be gated `if: github.event_name == 'push'` (only the merge-to-main push validates). (b) **`HEAD^` tolerance still breaks on consecutive merges** — after two squash-merges without an intermediate rebind, the binding sits at `HEAD^^`; the correct predicate is `git merge-base --is-ancestor <bound> HEAD` (accept any ancestor, reject non-ancestors). When merging such PRs, `mergeable_state: unstable` with all jobs green is usually the GitHub check-run aggregation race (old failing run + new passing run on the same SHA): read the truth from `GET /actions/runs?branch=…&per_page=5` → `/jobs` (not `/commits/<sha>/check-runs`, which can serve stale objects), then merge with `{"merge_method":"squash","expected_head_sha":<head>}`.
    - **Unit tests asserting the ancestry/`== HEAD` relationship fail on PR checkouts for the same reason (validated PR #51/#52).** On a PR, GitHub checks out `refs/pull/N/merge` — a synthetic merge ref whose `HEAD` is NOT on main's history — so a test calling `update_evidence_binding.check()` and asserting `findings == []` fails on CI (`STALE current=… head=<merge-ref-sha>`) while passing locally on the branch head. Fix the TEST, not the tool: assert the logic's known outcomes instead of a fixed answer — for any finding, require it to be the expected `STALE` shape (`f.startswith("STALE")`), which passes on both a plain main checkout ([] → loop no-op) and a PR merge ref (STALE → shape-checked). Keep the strict negative control (`test_check_rejects_foreign_sha` with a `0*40` SHA) as the real invariant.
    - **`git reset --hard origin/main` silently discards uncommitted patches.** If you patched a script and then synced main with a hard reset, the edit is gone with NO `git status` signal (the file matches HEAD again — it looks clean). After any hard reset, grep the file for a string only your patch added before continuing; this session lost a 37-line freshness patch this way and burned a debugging loop on a phantom "STALE" caused by the reverted file.
    - **SBOM must cover the vendored packages**: if the project ships an SPDX SBOM (`sbom-v42.spdx.json`), a fresh one only lists project binaries + one PyPI dep (4 packages) and silently omits all 30+ vendored skill trees → evidence-coverage gap. Fix: derive packages from SOURCE_REGISTRY entries with `integration_mode == vendor-adapt && license_verified` (this session: 4 → 53 packages; SPDXID must be unique, license from registry, `downloadLocation` = repo URL). Keep a `verify_sbom.py` in the aggregate chain that checks: SPDX 2.3 version, SPDXID uniqueness, `documentNamespace` ends with a 12-char tree SHA, and every vendor-adapt registry entry appears as a package — so future batches that forget to extend the SBOM fail locally instead of silently shipping an incomplete inventory.
17. **Namespace-drift fixes must be a 3-way sync: data files + verifier hardcodes + tests.** When a legacy namespace (`open-design/`, `work-lab/`) survives in active JSON (benchmark-registry `schema_version`, 12 briefs' `schema_version`), the fix is not just the data: `verify_benchmark_registry.py` hardcodes the OLD expected string (`"open-design/benchmark-registry/v1"`) and will FAIL after you fix the data, and the unit test (`test_benchmark_registry.py`) re-runs that script so it fails too. Grep the verifier scripts AND tests for the old namespace string before/after editing data. Legit keepers: host-adapter directory names (`adapters/hosts/open-design/`), plugin protocol filenames (`open-design.json`), external product names (`open-design.ai`), and `workflows-archive/` files — classify remaining hits by content before mass-replacing.
18. **Release-gate acceptance markers: never match acceptance by keyword presence in prose — require an explicit structured marker.** The first marker design checked `"通过" in readme or "PASS" in text.upper()`; the evals README's evidence-discipline prose ("不用单张 AI 图作为**通过**证据") matched 通过 → gate wrongly reported `RELEASE_GATE=READY` (false positive on a not-yet-accepted release). Fix: require an explicit token like `DL-REL-001: ACCEPTED|验收通过|DONE` (regex-scoped to the marker line). **Marker lifecycle pitfalls (validated on PR #41/#42):**
    - **The marker must be added to `.gitignore`** — it's a dynamic artifact; untracked it shows as `??` in `git status --porcelain`, which makes the release gate's own DIRTY-WORKTREE check fail forever.
    - **Verify the marker path resolves to the repo root correctly.** `verify_design_lab.py`'s `ROOT` is `design-lab/scripts/` (not `design-lab/`), so `ROOT.parent / "design-lab/config/..."` silently wrote to `design-lab/design-lab/config/...` and the file never appeared at the consumer's path. Repo root is `root.parent.parent` from `scripts/`.
    - **Do NOT swallow marker-write failures with a bare `except Exception: pass`** — that hid the wrong-path bug until the marker was checked on disk. Write the marker, then assert `marker.exists()` and print the resolved path in the verifier output.
    - **Marker must bind the exact SHA**: write `ok <HEAD-SHA>` and have the release gate reject a stale marker (`VERIFY-CHAIN-STALE marker=… head=…`) — exact-SHA semantics, not just existence.
    - **Consumer-side acceptance logic also needs the false-positive guard**: the release gate's human-acceptance check is a sibling of the marker check — both must match explicit tokens, never prose substrings.
19. **Human-acceptance workflow: ship the E1 scoring tool so the human step is a fill-in-the-blank (validated PR #49/#50).** A release gate gated on human acceptance (DL-REL-001) needs a deterministic scoring entry point, not just rubrics. Pattern that worked: `score_artifact.py --list` (enumerate rubrics from `evals/rubrics/*.rubric.json`, print axes/accept thresholds) + `--rubric <r> --scores <sheet.json>` where the sheet is `{"artifact": "…", "reviewer": "…", "scores": {"axis-id": 0..10}}`. The tool: reads rubric `scale` + per-axis `weight`, computes weighted mean, applies `acceptance.{accept,revise,reject_below}` thresholds → `SCORE_ARTIFACT=ACCEPT|REVISE|REJECT`, and **fail-closed on missing axis scores or out-of-range values** (returns rc=1 with the missing axes listed). Emits a jury-record-shaped JSON (schema_version + reviewer + thresholds) so the verdict is both human-calibrated and machine-computed. Test all three states (ACCEPT / REJECT / missing-score error) before shipping.
    - The older `score_visual_quality.score_report` has a DIFFERENT, stricter contract than `score_artifact` (validated PR #61): `report["hard_gates"]` is a LIST of gate dicts each with an `id` field (`[{"id": "source-and-license", "result": "pass", "pass": true}]`), NOT a dict keyed by gate id. `_hard_gate_maps` iterates the list and keys by `gate["id"]`; passing a dict-of-gates makes every gate "malformed" and the report silently rejects. Before writing unit tests against any scoring verifier, READ the script's parsing function (e.g. `_hard_gate_maps`, `_axis_item`) and build fixtures to the REAL data contract — two of six first-pass tests failed purely on fixture shape (dict vs list-of-dicts), not on logic. Also note the decision semantics: `blocking = missing_axes or invalid_axes or missing_evidence or failed_gates or missing_hard_gates or malformed_gates` → ANY blocking condition forces `reject` regardless of weighted score; tests should cover accept / low-score reject / missing-axis reject / failed-hard-gate reject / missing-evidence reject / out-of-range reject (the six-state matrix that passed).
    - Every scoring/validation tool in the repo has its own contract — read each before testing (validated PR #63, third scoring round). `score_design_critique.score_critique(critique, threshold=8.0)` reads `critique["scores"]` as a LIST of `{axis, score, weight, evidence}` dicts (scores 0–10, weight > 0, missing `evidence` → `missing_evidence` list) plus `critique["automated_checks"]` (list of `{id, result, severity}`; `result=="fail" && severity=="blocker"` → blockers). Accept = `weighted >= threshold AND not blockers AND not invalid_scores AND not missing_evidence`. `validate_style_recipe.py` is a 20-line argparse CLI taking ONE positional `recipe` file: constraints are `project_dna.weight >= 0.5`, combined `lineage_weights` <= 0.45, combined `master_method_refs` weight <= 0.35, and the `originality_guard.name_free_generation_prompt` must not contain a master id (dash→space normalized, len > 3). `verify_minigame_domain_pack` prints `MINIGAME_DOMAIN_PACK_BOUNDARY_PASS contract=manifest fixture=minigame-runtime evidence=E2`.
      - **Iteration-comparison tools (validated PR #64, fourth scoring round)**: `compare_visual_iterations.compare_reports(before, after, tolerance=0.0)` reads `report["axes"]` as a dict whose values may be **scalars OR `{"score": n}` dicts** (`_score_for` handles both — build fixtures with both shapes), plus `report["overall"]`/`report["score"]` for the overall line (falls back to the axis mean). Returns `{overall_delta, axis_deltas, regressions}` where `regressions = [axis for delta < -abs(tolerance)]` — the CLI exits 1 if any regression. Test matrix: improvement (no regressions), real regression (in `regressions` + negative overall_delta), tolerance absorbing a small drop, and a NEW axis appearing in `after` (delta = its full score, no crash). `verify_open_design_assistance` is a read-only boundary check that must exit 0 bare — assert rc==0 only, no output-shape coupling.

## CI-only failures: local green but CI red (validated 2026-08-13)

When tests/verifiers pass locally but the GitHub Actions run fails, in this order:

1. **Empty directories are NOT tracked by git.** A `git archive HEAD` checkout (what CI effectively sees) drops empty dirs. If a verifier checks `path.exists()` for `knowledge/sources/` etc., it fails on CI but not locally. Fix: `.gitkeep` in every empty tracked dir. **Local simulation**: `git archive HEAD | tar -x -C <tmp>` + `mkdir <tmp>/.git` reproduces the CI checkout exactly — run the failing verifier there before pushing again.
2. **CI may lack pytest.** The repo's `requirements.txt` may install only jsonschema. A unittest-style test invoked as `python -m pytest ...` fails with "No module named pytest". Fix: run tests as `python scripts/run_python_tests.py` (unittest discovery) or `python -m unittest <module> -v`.
3. **New Python files need SPDX headers.** A License-hygiene gate fails on new `.py` files lacking `# SPDX-License-Identifier: MIT`. Add on creation, not after the failure.
4. **CI log access via API can 403** for job logs. Get failure details from `check-runs/{id}/annotations` instead, or reproduce locally (see #1) — don't burn turns fighting the logs endpoint. **BUT the full log IS retrievable without admin (validated 2026-08-14):** (a) the workflow's `permissions:` block must include `actions: read` (bare `contents: read` makes `GET /actions/jobs/<id>/logs` 403); (b) the endpoint returns **302 to an S3 signed URL** — urllib does NOT follow it (403 again), so use `curl -sL --noproxy '*' -H 'Authorization: token <token>' -H 'Accept: application/vnd.github+json' .../actions/jobs/<id>/logs` and read the real 200 body. Add `-w '\n%{http_code}'` and split on the last newline to confirm. A 302 without `-L` yields an empty body — follow it. This gives the actual pytest traceback when annotations are too terse (`Process completed with exit code 1` is useless; the real `FAIL: test_x ... AssertionError` is in the log body).
5. **Fetch/merge flakiness**: `git fetch origin main` intermittently dies with SSL/connect errors on this user's network; retry with `-c http.proxy=http://127.0.0.1:7890`, or push via `git@github.com:` SSH. After a merge, always `git reset --hard origin/main` after a successful fetch — do NOT trust a stale `origin/main` ref. **When the proxy fetch itself dies with `schannel: failed to receive handshake, SSL/TLS connection failed` (Windows), add `-c http.sslBackend=openssl`** — the schannel backend is flaky through Clash; `git -c http.proxy=http://127.0.0.1:7890 -c http.sslBackend=openssl fetch origin main` is the reliable form.
6. **Interpreter-version wheel incompatibility: reproduce with the CI Python version before touching code (validated 2026-08-14).** Local green (py3.11) + CI red (py3.12, ubuntu) with NO code diff is classically a transitive binary wheel broken on the CI interpreter — real case: `rpds-py==0.30.0` (a `jsonschema` dependency) ships a wheel whose `rpds.rpds` binary module is missing/ABI-broken on Python 3.12, so `import jsonschema` fails in `test_oda4_0206_adapters.py` at module import time (collection error, not assertion). Diagnosis: check `uv python list` for a locally-installed interpreter matching CI's version (`cpython-3.12-...`), then run the EXACT failing command with that interpreter (`C:\Users\...\cpython-3.12-...\python.exe scripts/run_python_tests.py`) — the traceback appears locally in seconds. Fix is a requirements.txt pin (`rpds-py>=2025.6.0`), not a code change; verify by reinstalling into a `--target` dir + `PYTHONPATH` and re-running the failing test with the CI interpreter. Note: local `pip show rpds-py` shows the OLD version because the hermes venv's py3.11-built wheel leaks into the py3.12 run via shared site-packages — the `--target` clean-dir trick isolates it. Also: don't trust the check-runs annotation summary for collection errors; the run's step log (see #4) has the full `ModuleNotFoundError` traceback.
7. **Some verifier scripts cannot be importlib-loaded for unit tests — run them as subprocess instead (validated PR #55/#56).** Writing unit tests that `importlib.util.spec_from_file_location(...)` a verifier script can fail at exec time with a dataclass-related `AttributeError: 'NoneType' object has no attribute '__dict__'` when the script uses `@dataclass` + `from __future__ import annotations` (the dataclass machinery resolves string annotations against `sys.modules[cls.__module__]`, which is None for a bare spec load). The script is fine when run normally; only the import harness breaks. Fix: for such scripts, skip the load and drive the verifier as a `subprocess.run([sys.executable, str(SCRIPTS/<name>.py)])` in the test, asserting on rc + a `VERIFY_*=OK` regex in stdout. Keep importlib loading only for scripts you know are plain (no dataclass/annotations). If in doubt, write the subprocess form first — it also exercises the real CLI contract (exit code) rather than an in-memory function.
8. **Generated-index generators leave a phantom `M` in `git status` under Windows autocrlf (validated 2026-08-14).** After running `generate_capability_indexes.py` (or any generator that rewrites a tracked JSON), `git status` shows ` M design-lab/config/capability-index.json` while `git hash-object` matches HEAD and `git diff --text` is empty. Cause: generator writes LF, but `core.autocrlf=true` + `.gitattributes eol=lf` leaves the worktree in CRLF; git's stat layer flags the file even though the normalized content is identical. `git add --refresh` does NOT clear it. Fix: `git checkout -- <file>` to restore, or add the file with `git add` (git stores the LF form) — but do NOT ship the generator-run as part of a content batch; regenerate in the dedicated finalize batch (see 16). If a verifier run touches the index, restore it before committing so the batch diff stays clean.
